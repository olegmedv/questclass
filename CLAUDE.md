# КвестКласс 2 — правила проекта

Семейное учебное приложение: админы (родители) и ученики, задания с подключаемыми типами (видеоурок, тест, дело), прогресс, XP и монеты, магазин, герой. ТЗ — `docs/SPEC.md`; поведение оригинала и чеклисты паритета — `docs/spec/01–04`; эталон вида — `docs/reference-screens/`.

## Стек
- Node 22 LTS, TypeScript (strict), pnpm workspaces.
- API: Hono на `@hono/node-server`; Drizzle ORM + better-sqlite3 (SQLite, WAL); zod для валидации.
- Web: Vite + React 19 SPA, React Router, TanStack Query. SSR не используется.
- Видео: HLS (hls.js) со своими контролами; запасной вариант — MP4 с Range.
- Тесты: Vitest (unit и интеграция API на временной SQLite); e2e — Playwright (позже).
- Деплой: один Docker-контейнер за общим Caddy на VPS (сеть `shared_web`). Образ собирает GitHub Actions и публикует в приватный GHCR, сервер только скачивает его. Node раздаёт и API, и собранную SPA, и медиа (Range); Caddy — только TLS и `reverse_proxy`, его тома и чужие проекты не трогаем.
- Ассеты оригинала для MVP лежат в git, пережатые (WebP/OGG), только нужное.

## Структура
```
apps/api/          сервер: src/modules/<домен>/{routes,service,repo}.ts, src/db/{schema,migrations}, src/task-types/<type>/
apps/web/          SPA: src/app (роутинг, провайдеры), src/templates, src/screens/<area>, src/features/<домен>, src/task-types/<type>/{Editor,Player}.tsx
packages/shared/   zod-схемы, DTO, контракты типов заданий (config/submission), общие константы
packages/ui/       дизайн-система: tokens.css, компоненты, галерея для /dev/ui
tools/lesson-prep/ CLI на ПК админа (в MVP — команда import)
deploy/            Dockerfile, фрагмент Caddy, скрипты бэкапа и деплоя
docs/              ТЗ, спеки, ресёрч, скриншоты, PLACEHOLDERS.md
QuestClass-Source/ исходники оригинала — ТОЛЬКО ЧТЕНИЕ, не в git
```

## Правила (обязательные)
1. **Одно действие = одна вставка или изменение строки.** Никаких «всё состояние в одном JSON». JSON-колонки разрешены только для:
   - (а) type-specific `config` заданий и значений `settings`;
   - (б) **объектов-значений одной строки**, которые читаются и пишутся целиком и не участвуют в SQL-фильтрах, сортировке или агрегатах. Примеры: варианты ответа и evidence вопроса, снимок вопроса в попытке, сегменты расшифровки, payload аудита, объединённые интервалы просмотра одной строки `watch_progress`.

   Коллекции сущностей, межсущностное состояние и всё, по чему нужен запрос, — только отдельными таблицами.
2. **Чтение никогда не пишет в БД** (в том числе продление сессии: idle-таймаут ведётся подписанной cookie, без записи в БД).
   - Схема меняется только версионированными миграциями Drizzle (`pnpm db:generate`, файлы в git). Миграции применяются явно при старте, до приёма запросов.
   - Миграции только **расширяющие** (expand-only): новые таблицы и nullable/default-колонки. Удаление и переименование — отдельным шагом после релиза, который уже не использует старое. Так откат на предыдущий образ безопасен.
   - История не удаляется: в таблицах с историей FK `ON DELETE RESTRICT`. Пользователи деактивируются, задания и предметы архивируются. Физически удалить можно только то, на что ничего не ссылается.
3. **REST-ресурсы** (`/api/<ресурс>`). Эндпоинты-свитчи по полю `action` запрещены.
4. **Баланс = SUM(`ledger`).** Каждое начисление и списание — строка журнала с уникальным `idem_key`. Отмена — новая компенсирующая строка, а не удаление.
5. **Каталоги общие** (товары, комнаты, наряды, причины наград): отдельные таблицы, не копия у каждого ученика.
6. **Никаких захардкоженных id, имён, дат и разовых патчей** под конкретного пользователя. Всё конфигурируемое лежит в `settings`; секреты (ключи API, токены) — в `secrets`, зашифрованы мастер-ключом.
7. **Переменные окружения только для запуска:** `PORT`, `DATA_DIR`, `NODE_ENV`. Остальное настраивается в админке.
8. **Дизайн-система.** Экран = шаблон из `apps/web/src/templates` + компоненты из `packages/ui`. CSS под конкретную страницу запрещён. Цвета, отступы и шрифты берутся только из токенов `tokens.css`. Новый визуальный элемент сначала добавляется в `packages/ui` и в галерею `/dev/ui`.
9. **Заглушки.** Отсутствующий ассет выводится только через `<Placeholder kind label/>`, и для него обязательна запись в `docs/PLACEHOLDERS.md`.
10. **Типы заданий — плагины.** Каждый тип = zod-схема `config` и `submission` (shared) + `grade()` (api) + `Editor` и `Player` (web), регистрируется в реестре. Логика типа не размазывается по общему коду.
11. **Права.** Каждый маршрут API явно объявляет роль (`admin` | `learner` | `import-token`). Ученик видит только свои данные; ответы на тесты не уходят клиенту до сдачи.
12. **Время.** Часовой пояс установки задан в `settings` (по умолчанию `Europe/Kaliningrad`). «День» для серий и лимитов считается только через общий хелпер `dayKey()`.
13. **Бюджет сервера:** ≤200 МБ RSS на процесс. Никакого ffmpeg, Whisper, LLM и тяжёлых нативных зависимостей на сервере; всё тяжёлое — в `tools/lesson-prep` на ПК админа.
    - Dev-инструменты (sharp, ffmpeg, Playwright) разрешены в `scripts/`, `tools/` и тестах как devDependencies, но в серверный образ не попадают.
14. **Тесты проверяют поведение** через сервисы и HTTP-API на временной БД. Тесты вида «в исходнике есть строка» запрещены.
    - Видеофикстуры не коммитятся, а генерируются при подготовке тестов (`ffmpeg -f lavfi testsrc`).
    - Скриншот-базы e2e создаются только в Linux-контейнере Playwright (как в CI).
15. **Язык:** интерфейс по-русски; код, идентификаторы и коммиты — по-английски (описание коммита можно по-русски).
16. **Оригинал** (`QuestClass-Source/`) — справка по поведению и источник ассетов. Его код не копируется целиком, его архитектура не воспроизводится.

## Команды
- `pnpm install` — зависимости
- `pnpm dev` — api и web в режиме разработки
- `pnpm test` — все тесты
- `pnpm lint && pnpm typecheck` — проверки
- `pnpm build` — сборка
- `pnpm db:generate` — новая миграция из схемы

## Git
- Работа в ветках `feat/…`, `fix/…`, `plan/…`; в `main` — только через merge.
- Коммит = один пункт плана, сборка и тесты зелёные.
- В конце сообщения коммита: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Не коммитить: `ddatabase/`, `QuestClass-Source/`, видео, `.env*`, данные из `DATA_DIR`.
