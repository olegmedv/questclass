# КвестКласс 2 — ТЗ

**Цель.** Сделать с нуля, на своём сервере, приложение по идее КвестКласса с доступом из РФ без VPN.
- Визуал повторяет оригинал «примерно так же», но собирается из **единой библиотеки компонентов**, без уникальных страниц.
- Часть продуктовой логики переносится. Бэкенд, данные и API пишутся заново.
- Модель **универсальная**: админ и ученики, подключаемые типы заданий, трекер и магазин без привязки к одной семье.

Документ — верхний уровень. Подробности и построчные чеклисты лежат в модулях:

## 2. Сервер
- **Железо:** свой VPS; приложению отведено до 256 МБ памяти.
- **Соседи:** другие проекты владельца за общим Caddy.
- **Бюджет QuestClass:** ≤200 МБ RAM. Тяжёлых процессов на сервере нет: ffmpeg, распознавание речи и локальная LLM работают на ПК админа.
- **Диск.** Видео 480p — ~300 МБ/ч, вторая дорожка 360p добавляет ещё ~60%. При ~8 уроках в неделю и удалении через 30 дней после прохождения это ~10–20 ГБ, помещается. Без удаления набежало бы ~60–100 ГБ в год.
- **Проверка до запуска видео.** Скачать тестовый файл 50–100 МБ по HTTPS **без VPN** с домашнего Wi-Fi и с мобильного интернета ребёнка. С ноября 2026 зарубежные хостинги режут подсетями: «страница открывается, большой файл обрывается».

## 3. Визуал: дизайн-система, а не страницы
В оригинале около 23 страниц и 57 CSS-файлов, у каждой страницы свой стиль и слои заплаток. В новой версии:

1. **Токены.** Цвета, типографика, радиусы, тени, отступы и анимации берём из оригинала: тёмная тема, переменные `--q-*`, акцент `#f4c65f`. Это единственный источник стиля.
2. **Библиотека компонентов** (~20–25 штук): Button, Card, ItemCard, Modal/Sheet, Tabs, ProgressBar/Ring, StatChip (XP, монеты, искры), Badge, Avatar, StepList, EmptyState, Toast, Celebration (оверлей награды), MediaPlayer, QuestionCard, Form-поля, DataTable, Placeholder.
3. **Шаблоны экранов.** Любой экран — это шаблон плюс компоненты:

   | Шаблон | Где используется |
   |---|---|
   | **LearnerShell** — шапка со статами и нижнее меню | все экраны ученика |
   | **TaskPlayer** — шаги, медиа, прогресс, панель действий | любое задание любого типа: видеоурок, тест, дело |
   | **Catalog** — сетка ItemCard + карточка-модалка | магазин, коллекции, награды, желания |
   | **ProgressView** — история, серия, итоги | прогресс у ученика и у админа |
   | **AdminShell** — разделы, список или таблица, форма-редактор | все разделы админки по одному образцу |

4. **Правила:**
   - запрещён CSS под конкретную страницу;
   - новый экран — это композиция существующего;
   - если нужен новый компонент, он добавляется в библиотеку;
   - все компоненты видны на служебной странице `/dev/ui`.
5. **Сверка с оригиналом.** По `reference-screens/` проверяем общий вид: цвета, плотность, карточки, нижнее меню, модалки. Пиксель-в-пиксель не нужно.

### Заглушки
Все отсутствующие картинки выводятся одним компонентом `Placeholder` (тип плюс подпись), без битых ссылок. Каждая заглушка записывается в реестр `docs/PLACEHOLDERS.md` и закрывается, когда появляется реальный ассет.

Что известно сейчас:
- **Каталожная графика есть** в `QuestClass-Source/public/`, 466 МБ: персонажи, комнаты, альбомы, наклейки, награды, напоминания, звуки.
- **В R2 оригинала лежали только загрузки родителя**, и их у нас нет:
  - свои картинки товаров и наград;
  - свои картинки напоминаний;
  - ZIP-пак Roblox для набора;
  - файлы для Стара;
  - аудио студии голосов;
  - части EXE.

  Данные Саши не переносим, поэтому в новой версии это просто пустые слоты, которые админ заполняет загрузкой. До загрузки показывается `Placeholder`.
- **Мини-игры** (этап 2): три карточки игр с заглушками, пока нет исходников.

## 4. Видео: как отдавать
- **MP4 + Range.** Обычный MP4 с `faststart` браузер и так не качает целиком. Он запрашивает куски файла (Range) по мере просмотра и буферизует 30–60 с вперёд. Всё идёт по одному долгому соединению.
- **HLS.** Видео нарезано на сегменты по 4 с (~150–250 КБ), каждый сегмент — отдельный запрос. Плеер (hls.js / Video.js 10) повторяет упавшие сегменты и сам переключает качество 480p ↔ 360p на слабом мобильном. Для нестабильной сети это надёжнее.
- **Выбор:** основной вариант **HLS**. Нарезку делает инструмент на ПК админа (§5) или ручная команда ffmpeg, сервер только раздаёт файлы. Запасной вариант — MP4.
- ⚠ Если провайдер «замораживает» любое соединение с зарубежным IP после первых килобайт, не поможет ни один формат. Нужен прокси в РФ. Это покажет проверка из §2.
- **Доступ.** Сегменты отдаёт Node только при действующей сессии и только для заданий, видимых этому ученику.
- **Трекинг просмотра.** Интервалы по `timeupdate`, отправка пачкой раз в 15–30 с; одна строка `watch_progress` на (ученик, видео).

## 5. Подготовка уроков: локальный проект `lesson-prep`
Отдельный проект в этом же репозитории (`tools/lesson-prep`). Запускается **на ПК админа по требованию** («обработай эту папку»), а после работы гасит всё, что поднял, включая LLM. Сервер не нагружает. Повторяет ручной процесс оригинала, только автоматически:

1. **Прочитать файлы.** Папка с видео; один файл — один урок. Предмет и дата берутся из имени или манифеста.
2. **Залить на YouTube как бэкап.** YouTube Data API (`videos.insert`), видео **приватные**. Ограничения:
   - API-проекты без верификации Google и так грузят только приватные видео, для бэкапа это подходит;
   - квота по умолчанию ~6 загрузок в сутки;
   - запасной путь: залить вручную в Studio и передать инструменту ID видео.
3. **Подождать автосубтитры.** Инструмент сам опрашивает YouTube, пока русская ASR-дорожка не появится (обычно от минут до нескольких часов).
4. **Выгрузить субтитры с таймкодами.** ✅ Готово в `D:\User\repos\YTsubsdownloader` (`ytsubs.py`, yt-dlp, без скачивания видео). Как работает:
   - на входе `links.txt`: ссылки на видео или плейлисты, в том числе Studio; строка без ссылки задаёт предмет;
   - выбор дорожки: ручные ru/en → автосубтитры на языке оригинала → любые ручные;
   - на выходе `subs/<предмет>/<название>/<название>.<lang>[.auto].srt` + `.txt` со ссылкой;
   - уже скачанные видео пропускаются, видео без субтитров перезапрашиваются при следующем запуске.

   Уже выгружены 61 урок оригинала, предметы совпадают с алиасами оригинала. `lesson-prep` берёт этот модуль как есть.
   - ⚠ Если загружать через API без верификации Google, видео будут **приватными**. Тогда yt-dlp понадобятся куки аккаунта (`cookiesfrombrowser`). Нынешние видео открываются и без них.
5. **Сделать вопросы локальной LLM** на RTX 3060 Laptop (6 ГБ видеопамяти):
   - Ollama + модель уровня Qwen 7–8B Q4 (влезает в 6 ГБ, по-русски нормально);
   - расшифровка режется на куски по 5–10 минут: сначала факты с таймкодами, потом из фактов вопросы по JSON-схеме (вопрос, 4 варианта, ответ, evidence {start, end, цитата}); вопрос без цитаты-опоры отбраковывается;
   - ожидаемо единицы минут на урок; после пакета Ollama останавливается;
   - мощная модель не нужна, при плохом качестве можно переключить на API.
6. **Подготовить видео для приложения.** ffmpeg режет HLS 360p + 480p (сегменты по 4 с) и делает превью; на 3060 это быстро (NVENC).
7. **Закинуть в QuestClass.** API импорта (токен импорта выдаётся в админке): видео, расшифровка, черновик задания с вопросами. Загрузка возобновляемая; повторный импорт того же урока его обновляет, а не дублирует.
8. **Ревью и публикация в админке.** Админ правит вопросы, проверяет фрагменты по таймкоду и публикует. Фрагмент evidence становится подсказкой «пересмотри с 3:20 по 4:55».

Ручной импорт вопросов текстом или JSON (формат из README оригинала) остаётся всегда.

**В MVP** входит только сторона приложения: API импорта, хранение и раздача видео, плеер с учётом просмотра, ревью вопросов. Плюс минимальная команда `lesson-prep import` для готовой папки (HLS + JSON вопросов), чтобы проверить цепочку. Шаги 2–6 — этап 2.

## 6. ИИ-сервисы: что было и варианты
**Что реально использовал оригинал** (по коду и строкам в дампе БД):

| Сервис | Для чего | Доказательство в данных | Какой ключ спросить |
|---|---|---|---|
| **OpenAI** (API platform.openai.com) | Ответы Стара, разбор файлов родителя, ИИ-проверки | `star_service_credentials` содержит только `OPENAI_API_KEY`; `star_brain_usage` растёт ежедневно | API-ключ OpenAI |
| **Microsoft Azure AI Speech** — только Speech, не Azure OpenAI | Голос Стара `ru-RU-DmitryNeural` + распознавание речи | есть строка `star_speech` (регион + ключ Speech); `star_voice_usage` — 0,5–4,5 тыс. символов в день | ключ Azure Speech + регион |
| **Cartesia** | Запасной голос «Сергей» и распознавание на ПК | есть строка `star_cartesia_connections` | API-ключ Cartesia (не обязателен) |
| Web Speech (браузер) | Распознавание на телефоне без Azure | — | ключ не нужен |

- **Не использовались:** Amazon (AWS) — нигде. Azure OpenAI заложен в код, но таблицы `star_azure` в дампе нет. Голос «Лев» — таблицы `star_lev_preferences` нет. ElevenLabs и OpenAI TTS есть в коде и `.env.example`, но не подключены.
- **Отчёты родителю** (Telegram-бот, Resend) — токены в тестовой копии пустые, в живых данных не проверено.
- Хостинг оригинала — Cloudflare внутри ChatGPT Sites, ключей у вас нет и не нужно.
- **Ключи.** Значения зашифрованы ключом оригинала. Либо спросить у владельца сами ключи (OpenAI, Azure Speech + регион, при желании Cartesia), либо завести новые. В любом случае они вводятся в админке → «Настройки».

**Варианты для новой версии** (все за интерфейсами `TtsProvider` / `SttProvider` / `LlmProvider`):

| Задача | Вариант | Стоимость | Замечание |
|---|---|---|---|
| Озвучка | **Azure Speech F0**, голос Dmitry, как в оригинале | бесплатно до 500 тыс. символов/мес — в 8 раз больше вашего расхода | нужен аккаунт Azure; бессрочность бесплатного лимита проверить |
| Озвучка | Silero v5 / Piper — локально | бесплатно | качество ниже Azure; на сервере мало RAM, лучше заранее генерировать на ПК |
| Озвучка | Deepgram | — | ❌ русскую озвучку не поддерживает (только распознавание) |
| Озвучка | OpenAI TTS / ElevenLabs | платно / free ~10 мин в месяц | запасной вариант |
| Распознавание голоса ребёнка | Web Speech в браузере | бесплатно | как в оригинале |
| Распознавание | Azure STT F0 / Deepgram | бесплатные лимиты / $200 кредита | запасной вариант |
| LLM для Стара | OpenAI (мини-модель) | единицы $ в месяц | живой диалог, только через API |
| LLM для вопросов | локальная (Ollama) / Gemini / OpenAI | 0 / free tier / центы | Gemini на бесплатном тарифе учится на данных — для данных ребёнка не брать |

- **Кэш озвучки обязателен:** файл на диске по ключу `hash(voice + text)`. Повторяющиеся фразы (приветствия, подсказки, названия уроков) генерируются один раз. Постоянные фразы интерфейса можно сгенерировать заранее.

## 7. Архитектура
- **Фронт:** Vite + React SPA; собранную статику раздаёт тот же процесс Node. SSR не используем.
- **API:** один процесс Node (Hono или Fastify) + SQLite. Фоновые задачи — очередь в той же БД, по одной за раз.
- **Auth:** админ входит по логину и паролю; ученик — выбор аватара и PIN. Сессии в HttpOnly cookie.
- **PWA:** Serwist, шрифты в бандле, никаких внешних CDN.
- **Развёртывание:** один контейнер `questclass` в сети `shared_web` + блок в общем Caddyfile, не трогая другие проекты. Образ собирает GitHub Actions и публикует в приватный GHCR. Node раздаёт API, SPA и медиа (Range), Caddy только проксирует. Ежедневный бэкап.
- **Ассеты** оригинала для MVP лежат в git, пережатые (WebP/OGG), только то, на что есть ссылки.

**Принципы** (лечим болезни оригинала):
1. Одно действие = одна вставка или изменение строки. Никакого «всё состояние в одном JSON».
2. Чтение не пишет в базу. Миграции данных только явные и версионированные.
3. REST-ресурсы вместо одного роута на 78 действий.
4. Каталоги (товары, призы, наборы, ачивки) — общие таблицы, а не копия у каждого пользователя.
5. Баланс = сумма append-only журнала `ledger` с ключом идемпотентности.
6. Никаких захардкоженных id, имён и разовых патчей в коде.
7. Тесты проверяют поведение, а не наличие строк в исходниках.

| Пользователи | `users` (role admin/learner, name, avatar, pin_hash), `sessions` |
| Настройки | `settings` (key, scope установка/ученик, value json; в т.ч. `video_retention_days` = 30), `secrets` (key, value зашифрован мастер-ключом, updated_at) — ключи API, токены; в UI показываются замаскированными, вводятся заново, не читаются обратно |
| Контент | `subjects`, `tasks` (type, subject_id, title, config json по типу, xp, coins, status, release_at, sort), `task_assignments` (task, learner, unlock rule), `media` (kind, path, size, duration, delete_after), `transcripts`, `questions` (task_id, text, options, correct, image, evidence) |
| Прогресс | `task_progress` (learner, task, state, score, completed_at, **closed_by_admin**), `watch_progress`, `attempts` + `attempt_answers` |
| Экономика | **`ledger`** (learner, at, xp, coins, sparks, source_type, source_id, idem_key unique, note, created_by), `reward_reasons`, `chores` + `chore_completions` |
| Магазин и игра | `catalog_items`, `purchases` (requested → approved → fulfilled / owned), `equipped`; этап 2: `spark_draws`, `collection_sets` + `collection_progress`, `achievements` + `learner_achievements` |
| Уведомления (этап 2) | `push_devices`, `reminder_schedules`, `deliveries`, `messages` |
| Служебное | `jobs` (очередь), `tts_cache`, `audit_log` (действия админа) |

**Типы заданий** (плагин = `{схема config, Editor, Player, grade()}`):
- `video_lesson` — видео, правило просмотра (70%), банк вопросов, N случайных за попытку;
- `quiz` — без видео;
- `chore` — реальное дело с подтверждением админа;
- `external_game` — этап 2.
