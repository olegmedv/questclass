# 01 · Учебное ядро — спецификация для пересборки

Источник: `QuestClass-Source` (экспорт ChatGPT Sites «КвестКласс»), прочитан 2026-11-14. Ссылки вида `файл:строка` даны по исходнику; в минифицированных файлах строка = одна огромная строка, поэтому рядом указана функция/фрагмент. «Не проверено» = не подтверждено запуском (ничего не запускалось).

Маршруты ребёнка: `/` и `/new` рендерят `FocusApp lessonRefresh` (`app/page.tsx`, `app/new/page.tsx`); `/classic` — старый `QuestApp` (`app/quest-app.tsx`). Все ветки `!lessonRefresh` в `focus-app.tsx` фактически мёртвые (см. «Не переносить»).

## 1. Обзор модуля

Учебное ядро — это путь «видео YouTube → короткий тест → награда» для одного ребёнка (2–3 класс) под контролем родителя.
- Родитель ведёт **предметы** (категории) и **уроки** (одно YouTube-видео + банк вопросов 3–30 шт.), импортирует видео/плейлисты, тесты (текст/JSON/пакет), задаёт даты открытия, назначения и правило просмотра.
- Ребёнок видит на главной «следующий урок», смотрит видео во встроенном плеере с серверным учётом реально просмотренных секунд, затем проходит тест из **3 случайных вопросов** банка; ответы неизменяемы; награда (XP пропорционально верным, монеты целиком при ≥1 верном) выдаётся **один раз** на урок.
- Открытие уроков: ручной режим (очередь внутри предмета + даты + назначения) или автоматический «4 предмета по кругу».
- Вокруг: серия занятий (5 дней → бонус), обучение-тур, подсказка-фрагмент видео к вопросу, «пройти с мамой», отчёты-события (Telegram/почта), PDF-отчёт за период, родительский PIN-кабинет, тестовая копия и полный сброс прогресса.

### 2.1 Предметы (категории)

**Что видит/делает пользователь.** Ребёнок: сетка предметов с пиксельными иконками в окне «Выбери урок», иконка+название предмета на карточке урока. Родитель: Кабинет → Учёба → «Предметы»: список карточек предметов (иконка, «Уроков: N · Плейлистов: M»), «Добавить категорию», редактирование названия и картинки, удаление пустой категории, привязка плейлистов.

**Правила и логика.**
- Стартовый набор из 6 предметов (`lib/curriculum.ts:5-12`, `initialCurriculum`): russian «Русский язык», world «Окружающий мир», math «Математика», reading «Чтение», art «ИЗО», craft «Труд»; к каждому — плейлист `autoSync:false`.
- Имя: trim, схлопывание пробелов, 1–80 символов, уникально по `toLocaleLowerCase('ru-RU')` (`curriculum.ts:67-76`, `saveCategory`). Переименование обновляет `subject` у всех уроков категории.
- Удаление только если нет уроков и плейлистов (`curriculum.ts:77-81`), иначе «Сначала перенесите уроки и отключите плейлисты этой категории.» Кнопка удаления показывается только для пустой категории (`app/category-manager.tsx`).
- Картинка: выбор из встроенных ассетов (`ImagePicker group="category"`) или загрузка (`upload:`-ссылка, модуль изображений). По умолчанию для новой — `reading`.
- Урок можно перенести в другую категорию (`setLessonCategory`, `route.ts:100`).
- Ребёнку категории отдаются без URL плейлистов (`childState`, `quest-model.ts:31`).

**Данные.** Subject{id,name,image}.

**Экраны и визуал.** `app/category-manager.tsx` (`CategoryManager`, `CategoryPicker` — shadcn Select «Все категории»), `EditorScreen` (полноэкранный диалог редактора). CSS: `quest-style.css` (`.category-card`, `.category-form`), тёмные переопределения `focus-theme.css`. Иконки: `public/game/subjects-pixel/{russian,math,world,reading,art,craft}.png` (через `GameImage` внутри `PixelSubjectIcons`), спрайт `public/game/subjects.png` (классика/родитель).

### 2.2 Плейлисты YouTube и импорт видео

**Что видит/делает пользователь.** Родитель: «Видео / плейлист» → выбрать категорию, вставить ссылку → «Прочитать ссылку» → список полученных видео с редактируемыми названиями → «Сохранить в категорию». В «Предметах»: «Привязать плейлист», переключатель «Проверять новые видео при входе родителя», «Обновить плейлист», «Обновить все плейлисты», «Отключить ссылку», последняя ошибка/дата синхронизации. Тосты «Добавлено: N. Уже были: M…».

**Правила и логика.**
- Разбор ссылки `parseYoutubeLink` (`curriculum.ts:25-37`): только `https:`, хосты `youtube.com`, `www.youtube.com`, `m.youtube.com`, `youtu.be`. Есть `list=` → плейлист (id `[A-Za-z0-9_-]{10,150}`), приоритет над видео. Иначе videoId из `youtu.be/<id>`, `?v=`, `/shorts/<id>`, `/embed/<id>`; строго 11 символов.
- Список видео плейлиста читается **на клиенте** скрытым YouTube iframe-плеером (`app/playlist-reader.tsx`): `getPlaylist()` опрос каждые 400 мс, список считается готовым, когда не меняется 1,5 с; дедлайн 20 с; загрузка IFrame API — 15 с; >1000 видео → ошибка «Разделите его на несколько частей». Чтение плейлиста не засчитывает просмотр.
- Названия — серверный oEmbed (`previewVideos`, `route.ts:45`): 1–100 id за вызов, параллельно по 8, таймаут 5 с на видео, title обрезается до 150; при неудаче «Урок N».
- Импорт `importVideos` (`route.ts:101-108`) → `mergeVideos` (`curriculum.ts:94-102`): дедупликация по videoId **по всем урокам**; новые — черновики: `minutes:10, xp:100, coins:350 (DEFAULT_LESSON_COINS), published:false, releaseAt:'', questions:[]`, `sourceId` плейлиста; у плейлиста обновляются lastCheckedAt/lastSyncedAt/videoCount, lastError очищается. Лимит 1000 уроков всего (`MAX_LESSONS`).
- Плейлист в категории дедуплицируется по (category, playlistId) (`savePlaylist`, `curriculum.ts:82-93`); ссылка без `list` → ошибка «Отдельное видео добавляется во вкладке «Уроки».»
- Автосинхронизация: при открытии кабинета в очередь попадают плейлисты с `autoSync && now-lastCheckedAt ≥ 1 ч` (`quest-app.tsx:114`); обрабатываются последовательно `PlaylistUpdater` (`category-manager.tsx`), есть «Остановить». Ошибка → `playlistFailure` (сохраняет lastError, lastCheckedAt). Синхронизация только добавляет, никогда не удаляет и не меняет тесты/награды.
- Отключение плейлиста (`deletePlaylist`) не трогает уроки.
- Техническое имя видео (дата записи «2026-09-08 10-11-12 математика», «Урок 5», только цифры, = videoId) заменяется известной темой из карты `lib/lesson-titles.json`, дата из имени переносится в `lessonDate` (`lib/lesson-titles.ts`). Выражения вида «2 + 3» не трогаются.

**Данные.** PlaylistSource; Lesson.sourceId.

**Экраны и визуал.** `app/content-importer.tsx` (`VideoImporter`), `app/playlist-reader.tsx` (`.playlist-preview`, iframe высотой 260), `app/category-manager.tsx` (`.playlist-source`, `.playlist-updater`, `.sync-results`). CSS: `quest-style.css` (`.importer`, `.import-preview`), `focus-theme.css`.

### 2.3 Урок и редактор урока (родитель)

**Что видит/делает пользователь.** Кабинет → Учёба → «Уроки и задания»: заголовок «Учебный маршрут», блок назначений (2.9), фильтр категории, кнопки «Пакетное добавление», «Загрузить тест», «Создать урок вручную». Пустое состояние «Добавьте первый урок» + «Взять пример по математике» (подставляет 3 демо-вопроса). Карточка урока: «{№}. {Предмет} · Назначен ребёнку | Открыт по порядку | Черновик», название, ✎, «Дата урока: ДД.ММ.ГГГГ · N вопросов в банке · X XP · Y монет», «Перенести в категорию», «Разрешить ещё одну попытку» / «Повторная попытка открыта», «Подтвердить просмотр вручную», 🗑 (только неначатый), «Последняя попытка: s/n» / «Тест начат, ответы сохраняются».

Редактор (полноэкранный `EditorScreen`, «Видео, вопросы и награды»): Название, Категория, «Длительность, минут», «Ссылка на видео YouTube», «Короткое описание», «Награда XP», «Монеты», «Открыть не раньше» (datetime-local), «Банк вопросов — В попытке — 3 случайных», вопросы (текст + 4 варианта с радио «правильный»), «Удалить вопрос» (если >3), «Добавить вопрос» (до 30), переключатель «Открыть ребёнку» («После предыдущего урока этой категории и указанной даты. Выключено — черновик.»).

**Правила и логика.**
- Схема `lessonSchema` (`route.ts:40`): title 1–150, subject 1–80, description ≤1500, videoId пусто или 11 симв., minutes 1–240, xp 1–1000, coins 0–1000, releaseAt пусто или валидная дата, questions 0–30, lessonDate пусто или строго `parseLessonDate`. `published` требует video + ≥3 вопросов. Id вопросов уникальны.
- Вопрос (`route.ts:39`): text 1–1000, ровно 4 варианта, текст 1–300, id вариантов уникальны, тексты уникальны без учёта регистра, correct ∈ вариантов; image/helpVideo по 2.16/2.15.
- Новый урок: id генерирует сервер; лимит 1000. По умолчанию `minutes 10, xp 100, coins 350`, категория = текущий фильтр или первая (`quest-app.tsx:51,118`).
- Редактирование запрещено, если по уроку есть **любая** попытка («Тест уже начат. Создайте новый урок, чтобы сохранить историю.»); смена видео запрещена, если начат просмотр (`route.ts:117`). Снятие публикации убирает урок из назначений.
- Удаление: только если нет попыток и записи просмотра (`route.ts:118`); подтверждение AlertDialog «Удалить урок?».
- Ссылка на видео в редакторе: принимает голый id или URL (`formatVideo`, `quest-app.tsx:52`); ссылка на плейлист → «Добавьте ссылку на отдельное видео».
- «Подтвердить просмотр вручную» (`manualWatch`, `route.ts:141`): работает даже для закрытого урока; создаёт просмотр `done`, duration = minutes×60, completionKind `parent`; отчёт «Просмотр подтверждён родителем. Тест ещё не завершён.»
- Массовая смена наград: Награды → «Монеты и опыт» → «Награды за все уроки» (`app/parent-lesson-rewards.tsx`, `setAllLessonRewards`, `route.ts:111-116`): XP 1–1000 и/или монеты 0–1000 для **всех** уроков, включая черновики; полученные награды не пересчитываются.
- Поле `minutes` в новом детском UI не показывается (используется только для ручного подтверждения и в классике).

**Данные.** Lesson, Question, Option.

**Экраны и визуал.** `app/quest-app.tsx` → `ParentPanel` (строки 104–125, вкладка `lessons` — строка 122, редактор — строка 121), `app/editor-screen.tsx`, `app/parent-lesson-rewards.tsx`, `app/integer-input.tsx`. CSS: `quest-style.css` (`.admin-lesson`, `.question-editor`, `.option-edit`, `.lesson-editor`), `parent-workspace.css`, `focus-theme.css`.

### 2.4 Импорт вопросов (текст / JSON / промпт для ИИ)

**Что видит/делает пользователь.** «Загрузить тест от нейросети»: выбор урока («Предмет · Название»), «Выбрать файл» (TXT/MD/JSON), «Промпт для нейросети» (копирует в буфер, «Промпт скопирован»), поле «Или вставьте готовый тест», раскрывашка «Показать образец текста и JSON», «Распознать вопросы» → предпросмотр «Проверьте: N вопросов» (верный помечен ✓) → «Сохранить тест к уроку».

**Правила и логика.** (`lib/import-tests.ts`)
- Обёртки ```` ```json / ```text ```` срезаются; `**` удаляется.
- Текст: заголовок вопроса `^(Вопрос\s*)?N[.)\-:]\s*текст` или `Вопрос N: текст`; варианты `A–D` или `А–Г` с `.`, `)`, `-`, `:`; ответ `Ответ:` / `Правильный ответ:` / `Correct answer:`. Строки до вариантов дописываются к тексту вопроса. До первого вопроса игнорируются строки на `#`, `Тест`, `Тема`; любая иная нераспознанная строка → ошибка «Не распознана строка: «…». Используйте образец формата.» Повтор буквы варианта или двух строк ответа → ошибка.
- Ответ: буква (лат./кир.) или цифра 1–4, иначе точный текст варианта, иначе id варианта (JSON).
- JSON: массив или `{questions:[…]}`; поля `text|question`, `options|answers` (массив или объект; элемент — строка или `{text|label, id, image}`), `correct|correctAnswer|answer` (число = индекс 0–3), опц. `image`, `helpVideo`.
- Итог: 3–30 вопросов; ровно 4 непустых различных (без учёта регистра) варианта; вопрос ≤1000, вариант ≤300. Id вариантов нормализуются в a–d, id вопросов — новые UUID.
- Файл: расширения `.txt .md .markdown .json`, ≤500 КБ для тестов (≤1 МБ для пакетов), пустой → ошибка, `\0` → «Сохраните файл в кодировке UTF-8», BOM снимается (`lib/read-import-file.ts`).
- Сервер `importQuestions` (`route.ts:110`): полностью заменяет банк; запрещено, если по уроку есть попытки. Публикация отдельно, в редакторе.
- Промпт (точный текст, `import-tests.ts`, `aiPrompt`): «Составь тест по этому уроку: 8 вопросов, в каждом ровно 4 разных варианта и один верный ответ. Уровень — 2 класс. Без двусмысленных вопросов. Верни только текст в формате: номер и текст вопроса, затем А) вариант, Б) вариант, В) вариант, Г) вариант, затем отдельной строкой «Ответ: Б». Между вопросами пустая строка. Не пиши объяснения после строки ответа.»
- Образец (`testTemplate`): 3 вопроса про 47, 8+5, 30−10.

**Данные.** Question/Option (+ image, helpClip из JSON).

**Экраны и визуал.** `app/content-importer.tsx` (`TestImporter`). CSS: `quest-style.css` (`.importer`, `.import-text`, `.format-help`, `.import-preview`, `.correct-preview`).

### 2.5 Пакетное добавление уроков

**Что видит/делает пользователь.** «Пакетное добавление уроков»: блок «Твой присланный пакет · 14 уроков · 6 предметов · 112 вопросов» + «Загрузить этот текст», «Выбрать файл TXT / MD», поле текста с плейсхолдером-образцом, «Как оформить текст», «Распознать все уроки» → «Найдено уроков: N · Вопросов: M», карточки с чекбоксом, статусом, ссылкой «Открыть видео на YouTube», ошибками/предупреждениями, раскрывашкой «Банк вопросов: K»; «Выбрать все доступные», «Снять выбор»; переключатели «Открыть готовые уроки ребёнку» (вкл.) и «Использовать даты как даты открытия» (выкл.); «Сохранить выбранные уроки (N)».

**Правила и логика.** (`lib/import-lessons.ts`)
- Формат: `# Предмет` (или `Предмет:`/`Категория:`), `Плейлист: url`, `## Урок N. Тема: Название` (заголовок `Урок …`), `Дата: ДД.ММ.ГГГГ|ГГГГ-ММ-ДД` (валидация реального числа), `Ссылка на урок|Ссылка|Ссылка на видео|Видео: url`, `Тема:|Название:` переопределяет имя, `Тест:`/`Вопросы:` игнорируются, далее вопросы в формате 2.4. Markdown, ```` ``` ````/`~~~`, `---` допускаются; вводный текст до первого урока игнорируется.
- Лимиты: ≤300 000 символов, ≤100 уроков за раз; у ссылки на видео удаляются `list`/`index`.
- Ошибки по уроку: нет предмета, имя не 1–150, предмет >80, нет ссылки, ссылка не на видео, плохой плейлист, разные ссылки, ошибки теста. Без теста — предупреждение «урок сохранится черновиком».
- Сопоставление предмета: по имени без регистра, `ё→е`, алиасы «русский→русский язык», «окр мир/окр. мир→окружающий мир», «литературное чтение→чтение»; иначе по URL плейлиста; иначе создаётся новая категория.
- Статусы предпросмотра (`previewLessonBatch`): `error` «Нужно исправить текст»; `skip` «Это видео повторяется в пакете» / «Урок уже начат — история сохраняется» / «У видео уже есть тест — без замены» / «Видео уже добавлено, новых вопросов нет»; `new` «Новый урок с тестом»/«Новый черновик»; `complete` «Добавить тест к существующему черновику». По умолчанию выбраны new+complete.

### 2.8 Автоматический режим «4 предмета по кругу»

**Что видит/делает пользователь.** Родитель: переключатель «Четыре предмета по кругу» в «Уроки и задания» (текст: «Русский → математика → окружающий мир → чтение, затем следующий круг… Шаг меняется после засчитанного просмотра, тест для перехода не нужен… ИЗО, труд, музыка и другие предметы автоматически не открываются…»). **Правила и логика.** (`lib/automatic-lessons.ts`)
- Основные предметы и порядок круга: `russian → math → world → reading` (`:2`).
- Готовность урока `lessonReady` (`:3-5`): валидный 11-симв. videoId, ≥3 вопросов, уникальные id, у каждого вопроса непустой текст, ровно 4 непустых варианта с уникальными id и текстами, correct среди них. **Флаг `published` не требуется.**
- Видимые ребёнку (`:15-18`): уроки основных предметов, готовые; плюс награждённые; плюс уже открытые ранее (`autoLessonOpenIds`). Сортировка по ключу даты (`dateKey`, `:6-11`): `lessonDate` → дата ISO в названии → дата `ДД.ММ.ГГГГ` в названии → дата releaseAt → `9999-12-31`; при равенстве — исходный порядок.
- «Просмотрен» = просмотр засчитан или есть награда (`lessonViewed`, `:20`).
- Выбор следующего (`nextAutomaticLesson`, `:44-50`): если закреплённый урок ротации ещё не просмотрен — он; иначе стартовый предмет = следующий за предметом закреплённого / сохранённый `nextSubject` / выведенный из истории (`inferredSubject`, `:23-31`: предмет последнего по времени просмотра + 1; без времени — последний предмет с просмотрами + 1; иначе russian). Перебор предметов по кругу; внутри предмета — первый урок **после** самого дальнего просмотренного, непросмотренный, готовый, с наступившей releaseAt, видимый (`:32-43`). Ранние пропуски не рекомендуются, но остаются открытыми.
- Доступность (`automaticAvailable`, `:69-75`): видим И (просмотрен ИЛИ ранее открыт ИЛИ (основной предмет, дата наступила, это и есть следующий)).
- Ротация сдвигается **при засчитанном просмотре** закреплённого урока (`advanceAutomaticWatch`, `:63-68`), тест не нужен. Открытые уроки запоминаются навсегда (`rememberAutomaticOpenLessons`, `:99-108`) — повторное чтение/переупорядочивание не закрывает доступ.
- Включение режима сначала фиксирует все уже открытые уроки (`retainPreviouslyOpenLessons`, `:77-87`); выключение возвращает ручной режим; сброс прогресса настройку не меняет (`reset-progress.ts`).
- В авто-режиме назначения ребёнку не показываются (`assigned:false`, `assignmentOrder:-1`, `quest-model.ts:31`).
- Расхождение: `docs/automatic-lessons.md` говорит «По умолчанию выключен» и «Следующий открывается после успешного теста»; код включает режим принудительно миграцией (`upgradeAutomaticLessons`, `:88-92`, вызывается в `quest-store.ts:27`) и двигает круг по просмотру. **Принимать поведение кода и текст UI**; дефолт для новой семьи — решить продуктово (в оригинале фактически ON).

**Данные.** LearningSettings.autoLessons; AutoRotation{nextSubject, pinnedLessonId}; AutoOpenLesson.

**Экраны и визуал.** `app/lesson-assignments.tsx` (переключатель), главная (2.10), окно игр (2.17).

### 2.11 Плеер урока и учёт просмотра

**Что видит/делает пользователь.** Экран урока: шапка «← К урокам · {Предмет} · Стар»; кикер «ШАГ 1 · ВИДЕО» (или «ПОВТОРЕНИЕ», «ПОМОЩЬ К ВОПРОСУ»), H1 название, «Урок от …»; видео 16:9; панель «↺ 10 сек · ▶ Смотреть/❚❚ Пауза · ↻ 10 сек»; «Скрыть низ/Открыть низ», «На весь экран/Свернуть»; «Подключаем видео…»; раскрывашка «Видео не запускается?»; строка «Просмотрено N% · Нужно M%» + прогресс-бар (в свободном режиме бар скрыт, «Можно переходить к вопросам, когда будешь готов»); «✓ Место остановки сохранено»; кнопка «Перейти к вопросам» (disabled до выполнения правила); подсказка «Посмотри M% видео — вопросы откроются.»; описание урока; блок «Награда за пройденный тест: +XP в набор · +монеты» («Награда уже получена»).

**Правила и логика.**
- Правило просмотра (`lib/watch-progress.ts`): `strict` — 95%; `partial` — `minimumPercent` (UI 10–95 шаг 5; API целое 10–95); `free` — без процента, но засчитывается только явной кнопкой «Я готов к вопросам» (`freeWatch`). Дефолт `{strict, 80}`. Изменение правила применяется к незавершённым просмотрам при следующем `watchStart`/heartbeat; засчитанные не отзываются.
- `watchStart` (`route.ts:144-151`): урок должен быть доступен; создаёт запись при отсутствии; `resume:true` → стартовая позиция = min(lastPosition, duration); новая `sessionId` (старая вкладка получает «Видео открыто в другом окне. Открой урок снова.»); если правило уже выполнено — засчитать.
- Клиент: IFrame API (`https://www.youtube.com/iframe_api`), ожидание до 15 с; `playerVars {playsinline:1, controls:1, fs:0, rel:0, start:floor(resume), origin}`; таймаут готовности 15 с → ошибка «YouTube не подключил видео…»; «Загрузить видео заново». Сэмплер каждые 250 мс помечает «разрыв» при скрытой вкладке, перемотке назад >0,15 с или вперёд больше `Δt×rate+0,65 с` (`app/lesson-player.tsx`).
- Heartbeat каждые 5 с, а также на паузе/конце видео и при скрытии вкладки (видео ставится на паузу): `{duration, position, playing (state 1 или 0), visible, continuous, playbackRate}`.
- Сервер (`recordPlayback`, `watch-progress.ts:18-34`; валидация `route.ts:161-162`: duration 1–14400, position 0..duration+1, rate 0,25–4): секунды `[floor(lastPos), min(floor(pos), ceil(duration)))` добавляются в множество, только если playing && visible && continuous && 0<Δt≤20 с && 0<Δpos≤min(20, Δt×rate+0,75). Позиция и время обновляются всегда (перемотка задаёт новую точку). Процент = floor(уникальные секунды / duration × 100), ≤100. Повтор фрагмента процент не увеличивает.
- При достижении порога: done, completedAt, completionKind `tracked`, сдвиг авто-ротации, отчёт `watched` (2.23).
- `freeWatch` (`route.ts:152-158`): только в режиме free и с текущей sessionId.
- Перед переходом к вопросам плеер ставится на паузу и сохраняет позицию.
- Ошибки YouTube (`lib/youtube-player-settings.ts`): 100 «Видео удалено или доступно только владельцу», 101/150 «Автор запретил просмотр… Открой урок в YouTube», 153 «YouTube не смог проверить, из какого приложения…», иначе общее; к тексту добавляется «(код N)».
- «Видео не запускается?»: переключение плеера «обычный YouTube» (`youtube.com`, по умолчанию) ↔ «без персонализации» (`youtube-nocookie.com`), выбор в `localStorage['quest-youtube-player']` (если запись недоступна — в памяти + предупреждение); вложенная «Родителю: YouTube просит войти»; «Открыть урок в YouTube» (ставит паузу, сохраняет; просмотр вне приложения не учитывается, родитель может подтвердить вручную).
- Блокировка автозапуска → «Нажми «Смотреть» или ▶ в видео, чтобы запустить урок.»
- Старт урока ставит дневную паузу напоминаний (`markStudying`, `route.ts:179`) и отметку для ачивок — интеграции других модулей.

### 2.13 Тест: попытки, 3 из банка, ответы, награда

**Что видит/делает пользователь.** «Вопрос i из N» + полоска; H1 вопрос (подсвечивается при озвучке); картинка вопроса; ряд: кнопка помощи (?), «Послушать», переключатель «Читать автоматически»; 4 варианта-радио с буквами А Б В Г, картинками и кнопкой 🔊 у каждого; липкая кнопка «Ответить» и подпись «Выбери один вариант» / «Можно изменить выбор до ответа».

**Правила и логика.** (`lib/quest-model.ts`)
- `startAttempt` (`:34`): урок доступен И просмотр засчитан, иначе «Сначала заверши просмотр по правилам, выбранным родителем.»; урок уже награждён → «Этот урок уже пройден. Награда получена.»; последняя незаменённая попытка не завершена → вернуть её (продолжение); завершена и повтор не разрешён → «Новую попытку откроет родитель.»; банк <3 → «Родитель ещё готовит вопросы.»
- Новая попытка: 3 вопроса — криптослучайная перетасовка банка (Fisher–Yates на `crypto.getRandomValues`, `:28`), варианты тоже перемешаны; если порядок вариантов совпал с порядком этого же вопроса в прошлой попытке — циклический сдвиг на 1. Попытка хранит **снимок** вопросов (правки банка не влияют на историю). `momMode` наследуется от прошлой попытки.
- Ответ (`answerAttempt`, `:52`): только на **текущий** (первый неотвеченный) вопрос и только вариант из него; повтор того же ответа — идемпотентно; другой ответ на отвеченный — «Этот ответ уже сохранён и не меняется.»; ответ в заменённую попытку — ошибка. Выбор до нажатия «Ответить» можно менять.
- Завершение после последнего ответа: score = число верных; **passed = score > 0**; награда (`lessonTestReward`, `:51`): XP = floor(lesson.xp × score/total), монеты = lesson.coins целиком, если score>0, иначе 0. Награда записывается, только если урок ещё не награждён → одна на урок навсегда (кроме «с мамой», 2.14).
- Публичная попытка (`publicAttempt`, `:33`) без правильных ответов до завершения; после — разбор (`completedAttemptReview`, `:20-23`: текст, выбранный ответ, верный ответ).
- Озвучка: «Вопрос X из N. {текст}. Вариант А. …» (браузерный `speechSynthesis`/Android-мост, `app/voice.tsx`); авточтение по умолчанию ВКЛ, `localStorage['quest-quiz-voice']='on'|'off'`.
- Отчёт после завершения — 2.23; при прохождении — окно игр (2.17), XP уходит в «набор» (модуль коллекций).

**Данные.** Attempt, LessonReward.

**Экраны и визуал.** `FocusQuiz` (`focus-app.tsx:302-312`). CSS: `focus-style.css` (`.focus-option` рамка 2px радиус 12 min-h 70, текст 20px; `.focus-option.selected` синяя рамка; `.focus-confirm` липкий низ), `lesson-refresh.css` (варианты min-h 62/19px; ландшафт — 2 колонки, варианты справа), `focus-theme.css` (тёмные: поверхность `#18253a`, выбранное `#263f67`), `action-accent.css` (жёлтая квадратная кнопка помощи 44×44), `desktop-layout.css`.

### 2.14 Повторы, автоповторы и «Пройти с мамой»

**Что видит/делает пользователь.** Ребёнок при 0 верных: «Попробуем ещё раз», «Награда: 0 XP и 0 монет…», «Повторить видео», «Ещё одна попытка», «Чтобы завершить урок и получить награду, повтори тест…». На любом результате — «Пройти с мамой» → диалог: «Прежняя награда за этот тест отменится: X XP и Y монет…», «Все ответы верные — полная награда. Видео повторять не нужно. Старые ответы сохранятся в истории.», поле «Родительский код» (6 цифр), «Отменить награду и начать заново» / «Отмена». Плашка в тесте «Проходим с мамой · награда по новому результату». Родитель: «Разрешить ещё одну попытку» у урока; переключатель «Автоматически давать ещё попытку».

**Правила и логика.**
- `canRetryAttempt` (`quest-model.ts:32`): не заменена, завершена, не пройдена и (score==0 ИЛИ autoTestRetries ИЛИ retryAllowed). Поскольку passed = score>0, **любая неудачная попытка (0 верных) повторяется автоматически**; переключатель и кнопка родителя влияют только на старые попытки, где passed мог быть false при score>0. Пройденный тест (≥1 верный) повторить ради лучшего результата можно только через «с мамой».
- `retry` (родитель, `route.ts:138`): последняя попытка завершена и не пройдена → retryAllowed=true.
- `restartWithMom` (`route.ts:62-72`, `quest-model.ts:36-50`): проверка PIN на месте (те же счётчики/блокировка, что вход), идемпотентно по `requestId`; attemptId должен быть последней завершённой незаменённой попыткой; отменяет LessonReward урока (сохраняет `cancelledReward`), помечает все прежние попытки `supersededAt`, создаёт попытку `momMode` с **теми же** вопросами прежней попытки в новом порядке (вопросы и варианты перемешаны); видео не требуется. Неверный PIN → «Неверный PIN. Награда и результат не изменены.» Отчёт `mom_restart` (запись в историю).

**Данные.** Attempt.retryAllowed/momMode/supersededAt/restartRequestId/cancelledReward; LearningSettings.autoTestRetries.

**Экраны и визуал.** `app/mom-retake.tsx`, `app/lesson-assignments.tsx` (переключатель), карточка урока в кабинете (`quest-app.tsx:122`).

### 2.19 Серия занятий (streak) и связанные эффекты

**Что видит/делает пользователь.** Компактная строка «🔥 Серия занятий {progress}/5 ○—○—○—○ 🎁 ▾»; развёрнутая: 5 ячеек «День 1…День 5» (5-я ★), «За 5 дней подряд» / «Бонус получен!» +200 монет · +200 XP · +3 искры, правило «День засчитывается после просмотра урока и завершения теста. Вечером — предупреждение «Досмотри урок и заверши тест до полуночи, чтобы серия не обнулилась. Полученные награды останутся.» Значок Стара в шапке и фавикон меняют настроение. При пропусках — «запустение» на главной (пыль, паутина, пауки). При бонусе — праздничный ролик и полёт монет/XP/искр.

**Правила и логика.** (`lib/lesson-streak.ts`)
- День — календарный день Калининграда (UTC+2 без перехода, `lessonDay`, `:6`).

- `count`: длина непрерывной серии до последнего дня, по циклу 5: `((n−1) mod 5)+1`; если сегодня ещё не занимался и вчера был — показывается текущий счёт; при пропуске ≥1 дня — 0. Закрытый 5-дневный цикл виден только в свой день; на следующий день счёт 0 без «штрафа» (`:26-43`).
- Бонус (`syncLessonStreak`, `:46-59`): если сегодня засчитан и count кратен 5 → один раз за день (`lesson-streak:{день}`) начисление +200 монет, +200 XP, +3 искры в общий журнал + запись истории `lesson_streak`. 10 дней → два бонуса.
- `completedToday` (для «довольного» Стара) требует **пройденный** (passed) тест сегодня (`:8-11`).
- Настроение Стара (`lib/star-mascot.ts`, `starMood`): completedToday → satisfied; todayDone → revived; пропуск ≥3 → grave; ≥1 → skeleton; был когда-то → waiting; иначе watching. Картинки `/icons/stars-transparent-v7/{mood}.webp`, фавикон `{mood}-192.png`.
- Предупреждение (`lib/streak-notification.ts`): с 18:00 до 22:00 Калининграда, если count≥1 и сегодня не засчитан (этапы 18 и 21).
- Запустение (`lib/lesson-neglect.ts`): уровень 1/2/3 при 1/2/≥3 пропущенных днях; выключается родителем (`neglectEnabled`); не показывается в уроке/кабинете/обучении.
- Праздник (`app/streak-celebration.tsx`, `lib/streak-celebration.ts`): только для бонуса, начисленного сегодня, один раз на устройство (`localStorage['quest-streak-celebration-v1:{test|child}:{bonusId}']`); фаза видео (`/celebrations/streak-five-v1.mp4`, при запрете автозвука — без звука/кнопка), затем полёт 10 монет, 10 XP, 3 искр с нарастанием счётчиков до подтверждённых сервером итогов; reduced-motion — сокращённо; предпросмотр не меняет балансы.
- Раскрытость карточки (некомпактный вид) — `localStorage['quest-streak-expanded']`.

**Данные.** StreakDay; бонус как строка журнала начислений (reason `lesson-streak`).

**Экраны и визуал.** `app/lesson-streak.tsx` (`LessonStreakCard`, `StarBadge`), `app/streak-celebration.tsx`, `app/lesson-neglect.tsx`. ### 2.20 Обучение-тур для ребёнка

**Что видит/делает пользователь.** При первом входе тур открывается сам (если не отложен и не пройден). Шаги: Начать урок → «пиксельный урок» 5 с (учитель машет, колокольчик «Дзынь! ### 2.21 Вход в кабинет родителя (PIN)

**Что видит/делает пользователь.** «Родителям» → диалог «Настройка приложения» («Придумай PIN из шести цифр.», поля «Имя ребёнка», «PIN», «Войти») при первом запуске или «Вход для родителя» («Введи PIN из 6 цифр — проверка начнётся автоматически.»). Кабинет — диалог «Кабинет родителя[ · тестовая копия]» с кнопкой «Закрыть кабинет».

**Правила и логика.**
- PIN строго 6 цифр (ввод фильтрует нецифры, max 6); при настроенном PIN вход стартует автоматически на 6-й цифре (без повторной отправки того же значения) (`focus-app.tsx:159-160`).
- Хранение: PBKDF2-SHA256, 100 000 итераций, соль = случайный UUID, 256 бит hex (`quest-store.ts:48`).
- Setup: только если PIN ещё не задан; имя 1–40 (клиент подставляет «Игрок»).
- Неверный PIN: failedPins+1; при 5 → `lockedUntil = now+15 мин`, счётчик в 0; во время блокировки любой ввод (и верный) → «Слишком много попыток. Подождите 15 минут.» Ошибка возвращается **без отката транзакции**, чтобы счётчик сохранился (`route.ts:61`).
- Успех: счётчики в 0; токен = 2 UUID; хранится SHA-256 токена; сессия 15 мин **без продления**; хранить не более 5 (истёкшие удаляются, остаются последние 4 + новая); cookie `quest_parent` HttpOnly; Secure; SameSite=Strict; Max-Age=900.
- Выход (закрытие кабинета) удаляет сессию и cookie.
- `changePin` (`route.ts:120`): требует сессию, новая соль, остальные сессии удаляются. **UI в кабинете не найден** (только API).
- Все родительские мутации и `GET ?parent=1` проверяют сессию («Откройте раздел родителя с PIN-кодом.»). Родительский GET отдаёт полный банк с ответами; детский — без.
- Защита POST: только JSON, отказ при `sec-fetch-site: cross-site` или чужом Origin; тело ≤500 000 символов.

**Данные.** Profile.pinHash/pinSalt/failedPins/lockedUntil, ParentSession.

**Экраны и визуал.** `focus-app.tsx:295-296`. CSS `quest-style.css` (`.gate-dialog` max 440, `.pin-input` 26px, letter-spacing 10px, по центру). Референсы `docs/reference-screens/mobile/20-parent-pin-setup.png`, `21-parent-home.png`.
