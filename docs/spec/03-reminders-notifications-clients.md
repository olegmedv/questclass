# 03 · Напоминания, уведомления, клиенты

Источник: `QuestClass-Source/` (только чтение). Ссылки вида `файл → функция`. «Калининград» = Europe/Kaliningrad, UTC+2 без перехода на летнее время; в коде он местами зашит как `+02:00`/`+7200000`.

---

## 1. Обзор модуля

Модуль доставляет ребёнку (Саше) напоминания «пора заниматься» и личные сообщения мамы, а родителю — push-отчёты о событиях ребёнка. Каналов доставки три:
1) **Web Push** (VAPID + RFC 8291, без сторонних SDK) в PWA/браузере;
2) **поллинг из Android-APK** (WebView-оболочка раз в ~15 мин спрашивает `/api/native-notifications`, FCM не используется);
3) **внутри открытого приложения** (опрос сообщения мамы каждые 15 с).

Родитель управляет всем во вкладке кабинета «Сообщения и напоминания» (`ParentReminders`). Там четыре вкладки: «МАМА!», «Расписание», «Картинки», «Телефоны». Расписание: дни недели, целые часы 06–22, до 17 слотов, у каждого слота своя картинка, к которой автоматически подбирается текст. Есть автосмена картинок раз в 2 дня. В день, когда урок начат, напоминания останавливаются. Отдельно, ежедневно в 18:00 и 21:00, приходят предупреждения о том, что серия занятий обнулится. Клиентские оболочки: PWA (`public/sw.js`, manifest), Android (`android-shell/`: WebView, нативные уведомления, смена значка по времени, TTS, самообновление APK) и Windows (`windows-shell/`: Electron-оверлей Стара, окно КвестКласса, автозапуск, самообновление). Обе нативные оболочки обновляются по подписанной RSA ленте `/native-updates/releases.json`.

## 2. Фичи

### 2.1 Мамины напоминания: расписание

**Что видит/делает пользователь**
- *Родитель*: «Сообщения и напоминания» → «Расписание». Сначала видна сводка сохранённого плана: «Расписание Саши», бейдж «Включено/Выключено», строка «Пн, Вт, … · Калининград · N напоминаний», строка о серии, список «время → название картинки» с переключателем «Показать тексты сообщений», статус автосмены. Кнопка «Изменить расписание» раскрывает редактор:
  - переключатели «Напоминать Саше о занятиях» и «Предупреждать об обнулении серии»;
  - дни Пн…Вс;
  - слоты: время, картинка, удаление;
  - «Добавить напоминание»;
  - «Быстро заполнить по интервалу»;
  - «Смена картинок»;
  - липкая панель «Сохранить расписание».
- *Ребёнок*: системное уведомление с картинкой. Заголовок «КвестКласс · По расписанию», текст «Открой КвестКласс и начни урок.\n<строка картинки>», кнопка «Открыть уроки». Нажатие открывает `/new?reminder=1` (отдельной обработки параметра `reminder` в UI нет, открывается обычная главная; не проверено вживую).

**Правила и логика**
- Модель: `lib/study-reminder-model.ts`.
  - `validSettings`: `timezone` обязательно `'Europe/Kaliningrad'`; `weekdays` — непустой набор 0–6 (0 = вс); слотов 1–17; время по regex `^(0[6-9]|1[0-9]|2[0-2]):00$`; времена уникальны; `mood` 0–4; `imageId` — UUID (36 символов `[a-f0-9-]`); `pictureMood` 0–4; `noImage`. Слоты сортируются по времени.
  - Легаси-формат `{startHour 6–20, intervalHours 1|2, stages 1–5, последний час ≤22}` конвертируется через `reminderPreset`.
- Значения по умолчанию (`defaultReminders`): `enabled:false`, Пн–Пт, слоты 11:00, 12:00, 13:00, 14:00, 15:00, `mood` = 0…4. `reminderPreset(start,interval,count)` урезает `count` до `floor((22-start)/interval)+1`, `mood = min(i,4)`.
- README говорит «1–5 escalating, interval 1–2 h». Код допускает 17 слотов на любые часы, интервал есть только в пресете. Переносить поведение кода.
- «Добавить напоминание» (`count()` в `app/parent-reminders.tsx`) берёт следующий свободный час после последнего слота, иначе первый свободный. Новый слот получает `mood = min(index,4)`. Селект «Количество» сразу меняет число слотов, без «Заполнить».
- Когда слот срабатывает, `dueReminder(settings,pausedDay,now)` возвращает `{day,stage}`, если выполнены все условия: `enabled`; `pausedDay ≠ сегодня`; день недели (по Калининграду) в `weekdays`; есть слот с `hour == текущий час`.
- Диспетчер (`dispatchReminders`), обычная ветка, пропускает владельца, если:
  - включён `state.testing.enabled` или `state.testMode`;
  - сегодня уже был старт: любой `watch[*].lastAt ≥ полночь` или любая попытка `attempt.created ≥ полночь`, где полночь = `Date.parse(day+'T00:00:00+02:00')`. Это вторая защита на случай, если запись `paused_day` не удалась;
  - нет ни одного доступного урока без награды (`available(state,l) && !state.rewards[l.id]`);
  - нет активных устройств с ролью `child`.
- Приоритет: если в этот час положено предупреждение о серии (18–21), отправляется **оно вместо** обычного слота (см. 2.2).
- Идемпотентность: `INSERT OR IGNORE INTO study_reminder_deliveries(owner,day,stage,device_id,'sending')`, где `stage` = **час слота** (а не индекс). Поэтому перестановка слотов или смена картинки не приводит к повторной отправке в тот же час. Если вставка ничего не изменила, отправка пропускается (`skipped`). Перед отправкой состояние перечитывается: устройство всё ещё активно, слот всё ещё актуален, тестовый режим выключен. Иначе статус `cancelled`. Итоговые статусы: `accepted`, `failed`, `cancelled`, `unknown` (исключение до записи).
- Push: TTL 1800 с (30 мин), Topic `quest-study-reminder`, Urgency `normal`. Ответ 404/410 деактивирует устройство (`unsubscribePhone`).
- Пауза: `markStudying()` делает upsert `paused_day = сегодня`; если строки ещё нет, создаётся с `defaultReminders`. Триггер — J5. В UI при `pausedToday` показывается «Сегодня урок уже начат. Обычные напоминания остановлены…». Пауза снимается сама: на следующий день `paused_day ≠ день`.
- Текст (`reminderText(slot)`), заголовок превью `reminderTitle = 'Саша, пора делать уроки'`:
  - `noImage` → только «Открой КвестКласс и начни урок.»;
  - готовая картинка `ready:i` → инструкция + `momReminderLines[i]` («Мама верит в тебя 😄», «Мама ждёт 😉», «Мама уже округлила глаза 😳», «У мамы уже пар из ушей 😤», «Демон-мама на связи 😈 Верни маме улыбку!»);
  - курированная картинка → инструкция + первое предложение `curatedReminderTexts[sourceIndex]`;
  - загруженная пользователем → только инструкция.
- Сохранение: `POST /api/reminders {action:'save'|'shuffleImages', settings}`, тело ≤10 000 символов. `saveReminders` делает CAS-цикл (до 8 попыток, `UPDATE … WHERE settings=<старое>`). `deletedPictureIds` и `installedPicturePacks` сервер берёт из предыдущей версии, а не от клиента. Каждый `imageId` проверяется на принадлежность библиотеке.
- Сводка диспетчера: `{checked,due,accepted,failed,skipped,parentAccepted,parentFailed,at}` пишется в `study_reminder_clock` (id = 1) и отдаётся через `GET /api/reminders/dispatch` как `{ready:true,lastRun}`. Персональных данных в сводке нет.
- Доступ: браузерные запросы требуют аутентифицированного пользователя и действующей PIN-сессии (`requireReminderParent`: cookie `quest_parent`, хэш в `state.sessions`, TTL 15 мин). POST дополнительно требует same-origin и `Content-Type: application/json` (`rejectCrossSite`). Запрос без идентичности проходит только при `REMINDER_PRIVATE_SERVICE=1`.

**Данные**
- `ReminderSettings`: `enabled:boolean`, `streakEnabled?:boolean` (по умолчанию true), `weekdays:number[]`, `timezone`, `slots: ReminderSlot[]` (`time 'HH:00'`, `mood 0–4` (легаси), `imageId?`, `pictureMood? 0–4`, `noImage?`), `imageRotation?: {enabled, source:'all', nextDay?:'YYYY-MM-DD'}`, `deletedPictureIds?: string[]`, `installedPicturePacks?: ['20261003']`.
- Таблица `study_reminders(owner PK, settings JSON, paused_day TEXT '', updated_at)`.
- Таблица `study_reminder_deliveries(owner, day, stage, device_id, status, created_at)`, PK из 4 полей. Здесь же хранятся отправки сообщений мамы и похвалы: `day='mom:<id>'`/`'praise:<id>'`, `stage=0`.
- `study_reminder_clock(id PK, summary JSON)`.

**Экраны и визуал**
- `app/parent-reminders.tsx`, `app/parent-reminders.css`.
- Панель: градиент `#ffffff → #f6f4ff`, радиус 24px, padding 24px (≤600px: 17px/20px). Цвета: текст `#26324b`, приглушённый `#55647d`, линии `#d9dff3`, акцент (фиолетовый) `#6c56bb`, выбранное `#f0eaff`, бейдж `#ece8ff`/`#625095`.
- Тёмная тема `html[data-quest-theme=dark]`: `#1b2a43 → #22213c`, текст `#edf2ff`, акцент `#7259b7`, фокус `#c4b0ff`.
- Кнопки дней: минимум 44×44, радиус 13px, нажатая залита акцентом. Слот: карточка радиусом 18px, сетка «время | кнопка картинки (миниатюра 48×48 + название + «Выбрать»/«Закрыть выбор») | корзина 38px». Под слотом превью: жирный заголовок и текст с `white-space:pre-line`.
- Сводка: `<ol>` с колонками `52px | текст`, время 16px/700, цифры `tabular-nums`.
- Панель сохранения `position:sticky;bottom:0`: «Изменения ещё не сохранены»/«Всё сохранено».
- Иконки lucide: Bell, Clock, Send, Smartphone, Plus, Trash2, ShieldCheck, Shuffle, Pencil, ImageIcon. Компоненты shadcn: `Tabs`, `Switch`, `AlertDialog`.

**Внешние зависимости**: push-сервисы (2.7); планировщик Sites (заменить на cron).

### 2.2 Предупреждения об обнулении серии

**Что видит/делает пользователь**
- *Ребёнок*: в 18:00 и 21:00 (по Калининграду), если серия ≥ 1 дня, а сегодняшний урок с тестом не завершён, приходит push. Заголовок «Стар: сохрани серию занятий!», картинка `/reminders/star-streak.png` (192×192). Текст: `starStreakLine()` (серия, сколько дней до награды, сама награда 200 монет / 200 опыта / 3 искры за каждые 5 дней, предупреждение «до полуночи») или запасной вариант «Серия занятий — N дн. Досмотри урок и заверши тест до 00:00 по Калининграду, иначе серия обнулится. Уже полученные награды останутся.».
- *Родитель*: переключатель «Предупреждать об обнулении серии» (по умолчанию включён).

**Правила и логика**
- Расчёт: `lib/streak-notification.ts → streakWarning/dueStreakNotice`. Работает только в часы 18–21. `stage = 21`, если час ≥ 21, иначе 18. `expiresAt` = полночь + 21:00 для этапа 18 и + 22:00 для этапа 21. id = `streak:<day>:<stage>`. Условие: `count ≥ 1 && !todayDone`. «Сделано» значит просмотр плюс успешно завершённый тест (правило из модуля серии).
- Рассылается **каждый день**, без учёта `weekdays`, `paused_day` и признака «урок начат». Отключается только тестовыми режимами и `streakEnabled === false`.
- Ключ идемпотентности: `stage = 100 + 18|21` в `study_reminder_deliveries`. Push: Topic `streak-<day>-<stage>`, TTL = секунды до `expiresAt`. SW не показывает уведомление, если `expiresAt` уже прошёл. Тег `quest-streak-warning`.
- Перед отправкой проверяется, что `currentStreak.id === streak.id`. Если тест уже сдан, статус `cancelled`.

**Данные**: вычисляются из состояния серии, отдельно не хранятся. **Экраны**: строка в сводке расписания «Серия занятий: напоминания в 18:00 и 21:00, ежедневно до полного просмотра урока». **Зависимости**: push.

### 2.3 Картинки напоминаний: библиотека, ротация, удаление, паки

**Что видит/делает пользователь**
- *Родитель*, вкладка «Картинки»: заголовок «Все картинки N»; кнопки «Картинку» (загрузка) и «ZIP-архив»; раскрывающийся блок «Формат и размер картинки»; поиск, если картинок больше 6; плитки с превью, названием и кнопкой «Удалить».
- В редакторе слота открывается та же библиотека в режиме выбора: первая кнопка «Без картинки», у выбранной плитки отметка «Выбрана».
- Удаление подтверждается диалогом «Удалить картинку?» с пояснением: напоминания сохранят время и будут приходить с обычным текстом без картинки, в играх и магазине картинка останется.
- Блок «Смена картинок»: «Перемешать и сохранить» и переключатель «Менять автоматически через день».

**Правила и логика**
- Состав библиотеки (`reminderImageLibrary`), сверху вниз: неанимированные `state.game.assets` (новые первыми) → курированные (`curatedReminderImages` = 15 `momEmotionImages` + 47 картинок пака 20261003) → 5 готовых `ready:0–4` (`/reminders/mom-funny-{1..5}.png`). Из списка исключаются `deletedPictureIds`.
- URL картинки (`reminderImageUrl`): курированная → её статический `url`; `ready:i` → `/reminders/mom-funny-{i+1}.png`; иначе `/api/images?id=…`.
- Загрузка одной картинки (клиент): PNG/JPEG/WebP, ≤2 МБ → `POST /api/images` (2.13). После загрузки в режиме выбора картинка сразу выбирается: «Картинка загружена и выбрана. Сохраните расписание.».
- ZIP (`lib/reminder-image-archive.ts → readImageArchive`):
  - архив ≤20 МБ; ≤1000 записей; ≤100 картинок; каждая ≤2 МБ; суммарно после распаковки ≤50 МБ;
  - поддерживаются только сжатия store и deflate; без пароля, без ZIP64, без многотомных архивов;
  - имена в UTF-8 или CP866, Info-ZIP Unicode path (0x7075) учитывается при совпадении CRC;
  - пропускаются dot-файлы и `__MACOSX/`; проверяется CRC32; тип определяется по сигнатуре; анимированный WebP (VP8X, бит анимации) отклоняется;
  - картинки загружаются по одной, с прогрессом «Проверяем файлы: i из n» → «Загружаем: i из n · имя»;
  - по каждому пропущенному файлу показывается причина: «Не загружено: N — посмотреть причины».
- Удаление (`POST /api/reminder-images {action:'delete',id}`, ≤1000 символов): удаление **мягкое**. Id попадает в `deletedPictureIds`, а слоты с этой картинкой переходят в `noImage` (`withoutDeletedPictures`). Объект в R2 и `game.assets` не трогаются. Можно удалять и готовые `ready:i`.
- Перемешивание (`shuffleReminderSlots`, источник всегда `all`): пул = все не удалённые `ready:i` плюс все загруженные и курированные. Пул исчерпывается целиком, прежде чем картинки начнут повторяться. Слот по возможности получает картинку, отличную от его текущей и от картинки предыдущего слота; если после случайного выбора картинка совпала с текущей, её меняют местами с другой в пределах той же партии. Время слотов не меняется. Если пул пуст, ошибка «Сначала загрузите хотя бы одну картинку…».
- Автоматическая ротация: при включении или ручном перемешивании `nextDay = сегодня + 2 дня` (`nextPictureDay`, календарная арифметика в UTC-датах). `rotateReminderImages` срабатывает, если `nextDay ≤ сегодня`. Тогда она перемешивает слоты и сдвигает `nextDay` шагами по 2 дня, пока дата не станет больше сегодняшней. Запись через CAS, до 3 попыток. В тестовом режиме ротации нет. Вызывается при `GET /api/reminders` (у GET есть побочный эффект!), в каждом запуске J1 и в нативной ленте ребёнка. В UI: «Картинки меняются через день · следующая смена ДД.ММ.ГГГГ».

**Что видит/делает пользователь**
- *Родитель*, вкладка «МАМА!» (`app/parent-mom-messages.tsx`), заголовок «МАМА! · Отправить сейчас». В форме:

  - «Какой урок открыть»: «Мои уроки · без выбора конкретного» или доступный опубликованный урок, у пройденных пометка «· пройден»;
  - «Твой текст · необязательно», до 160 символов;
  - кнопки «Посмотреть у себя» (локальный предпросмотр) и «Отправить Саше».

В открытом приложении поверх всего, включая встроенную игру, появляется модальная карточка: огромное «МАМА!» цветом уровня, портрет с ореолом, текст, предмет и название урока, большая кнопка ▶. При показе карточки останавливаются озвучка, звуки интерфейса и видео. Нажатие ▶ закрывает игру и панели и открывает выбранный урок или следующий урок из очереди. Крестик или выход из диалога означает «закрыто» (dismiss).
- *Похвала* (`kind:'praise'`): заголовок «ИДЕАЛЬНО!», если 5 звёзд, иначе название; большая картинка награды; «+N монет · +M опыта»; кнопка ✓ «Отлично!».

**Правила и логика** (`lib/mom-message-model.ts`, `lib/mom-messages.ts`)
- Запрос: `requestId` (UUID, генерирует клиент; повторная отправка того же содержимого использует тот же id), `level ∈ {green,orange,red}`, `lessonId ≤80`, `text ≤160` (обрезается по краям), `emotionId` из списка или пусто.
- `sendMomMessage`:
  - нужен хотя бы один ребёнок (web-push или native), иначе ошибка «Нет подключённого телефона Саши…»; в тестовом режиме отправка запрещена;
  - тот же `requestId` с тем же содержимым возвращает существующее сообщение; с другим содержимым — ошибка;
  - если по этому id уже есть доставка, а сообщение заменено новым, ошибка «уже заменено»;
  - кулдаун 5 с между новыми сообщениями;
  - урок обязан быть опубликован и доступен;
  - у семьи одно активное `state.momMessage`, новое заменяет предыдущее;
  - срок жизни `expiresAt = now + 2 ч`.
- Доставка web-push: claim в `study_reminder_deliveries(day='mom:<id>',stage=0)`. При конфликте строка перезахватывается **только если статус `failed`**, то есть повторное нажатие «Отправить» заново шлёт только на неудавшиеся телефоны. Перед отправкой проверка «сообщение ещё текущее» (иначе `superseded`). Topic `quest-mama-message`, TTL 900 с, Urgency `high` для красного уровня, иначе `normal`.
- Native-устройства не получают push. Они считаются `queued`, и APK забирает сообщение при поллинге. Итог `{accepted,failed,total,queued}` пишется в `momMessage.push`. Тексты статусов для родителя: «Передано службе уведомлений: a из t… Прочтение ещё не подтверждено.» / «Сообщение сохранено для APK: N…».
- Ребёнок (`GET /api/mom-message?device=<sha256(endpoint)>&entry=<id>`): возвращается самое свежее активное сообщение (не открыто, не закрыто, не истекло) среди `parentPraises` и `momMessage`. Если устройство не зарегистрировано, ответ будет только при совпадении `entry` с id сообщения. В тестовом режиме всегда `null`.
- `POST {action:'open'|'dismiss',id}` проставляет `openedAt`/`dismissedAt`. Для этого достаточно идентичности, PIN не нужен.
- Клиент (`app/mom-message-receiver.tsx`):
  - работает, когда не открыт кабинет родителя, PIN-гейт и туториал и выключен testMode;
  - одно и то же сообщение не показывается повторно: id хранится в `sessionStorage['quest-mom-opened']` и в наборе закрытых в памяти;
  - при закрытии удаляет из URL параметры `mom` и `lesson` и закрывает системные уведомления с тегом `quest-mama-message` / `quest-praise-<id>`.
- Сигнал (`useMomSignal`): вибрация по уровню — green `[160]`, orange `[180,120,180]`, red `[260,100,260,300,260,100,260]`. Только для красного и только при включённых звуках интерфейса: синус, 4 качания 520→850→520 Гц по 0,45 с, громкость `0,12·volume`, длительность 1,9 с. Есть кнопка «Послушать сигнал». Звук не играет, когда вкладка скрыта.
- Похвала (`lib/parent-praise.ts`): `deliverPraise` использует claim `day='praise:<id>'`; перезахват разрешён при `failed` или при `sending` старше 60 с; Topic `quest-praise-<18 символов>`, TTL 86400; срок жизни похвалы 30 дней. При подключении телефона ребёнка `deliverPendingPraises` дошлёт до 5 неоткрытых похвал. Единственный в коде создатель похвалы — захардкоженная «награда за полотенце» (§3). Механизм `kind:'praise'` стоит перенести как общий: «родитель хвалит и начисляет».

**Данные**
- `MomMessage {id, kind?:'praise', level, emotionId?, image?, stars?, xp?, coins?, lessonId, lessonTitle, subject, text, createdAt, expiresAt, openedAt?, dismissedAt?, push?{accepted,failed,total}}`.
- В состоянии семьи: `momMessage?` и `parentPraises?: MomMessage[]`.

- В APK (UA содержит `QuestClassNotifications/1`) кнопка подключения переходит на `questclass://notifications?role&label&alerts`. Вместо «проверить» показана ссылка «Проверка и разрешение уведомлений APK» и пояснение про фоновую проверку раз в ~15 минут.

**Правила и логика**
- Web (`connect()`):
  1. если разрешение `denied`, ошибка;
  2. `Notification.requestPermission()`;
  3. ожидание `serviceWorker.ready` не дольше 12 с;
  4. если подписка в браузере есть, а на сервере устройство не найдено, подписка удаляется и создаётся заново (свежий endpoint);
  5. `pushManager.subscribe({userVisibleOnly:true, applicationServerKey:<VAPID public из GET /api/reminders>})`;
  6. `POST /api/reminders {action:'subscribe', subscription, role, label, alerts}`.
- Сервер (`subscribePhone`): id устройства = `sha256(endpoint)` в hex. Если endpoint принадлежит другому владельцу, ошибка. У одного владельца не больше **6** активных web-устройств. `created_at` (начало «подписки» на отчёты) сохраняется, если устройство было активно с той же ролью; иначе ставится `now`, и старая история не переигрывается. Подписка хранится зашифрованной (`seal`, AES-GCM на `REPORT_ENCRYPTION_KEY`). Endpoint и ключи в UI никогда не возвращаются. Подключение ребёнка вызывает `deliverPendingPraises`.
- Текущий телефон определяется на клиенте: `sha256(endpoint)` для web, `native:<UUID из UA QuestClassDevice/…>` для APK.
- Проверка (`testPhone`): не чаще раза в 10 с на устройство (CAS по `last_test_at`). Для ребёнка уходит payload первого слота с `test:true` и заголовком «Проверка · Саша, пора делать уроки». Для родителя — «КвестКласс · Проверка для мамы» / «Этот телефон получает отчёты о занятиях, играх и наградах Саши.». С `previewChild:true` родитель получает пробное напоминание ребёнка, роль при этом не меняется. Если картинка слота удалена, проверка уходит без картинки.
- Отключение (`unsubscribe`): web — `active=0` и `subscription.unsubscribe()` в браузере; native — `nativeDevices[id].active=false`.

**Данные**: `study_push_devices(id PK=sha256(endpoint), owner, subscription (sealed JSON {endpoint,keys{p256dh,auth}}), active, created_at, last_test_at, role 'child'|'parent', label, alert_settings JSON)`. Ответ `GET /api/reminders`: `{assets, settings, deviceCount, devices[{id,role,label,alerts,transport?}], pausedToday, publicKey}`.

**Экраны**: `.reminder-roles` — 2 колонки (≤600px — 1), карточка радиусом 16px, выбранная обведена фокусным цветом. `.reminder-device` — строка с нижней границей.

### 2.6 Push-отчёты родителю (parent alerts)

**Что видит/делает пользователь**: родитель с ролью «Мой телефон» получает push вида «КвестКласс · <имя ребёнка>: <глагол>» (до 100 символов). Текст — название урока и строки деталей отчёта, до 500 символов. Нажатие открывает `/new?parentAlerts=1`: PIN-гейт, затем раздел «История и отчёты». Картинки и кнопок действий нет, иконка `knowledge-spark-192`.

**Правила и логика** (`study-reminder-model.ts → alertCategories/reportCategory`, `study-reminders.ts → deliverParentReports/parentPayload`)
- Категории (по умолчанию все включены):

  | id | Название | Виды отчётов |
  |---|---|---|
  | `lessons` | Просмотр уроков | `watched` |
  | `tests` | Ответы на вопросы и результат теста | `passed`, `failed` |
  | `purchases` | Покупки и желания | `purchase`, `wish_requested`, `wish_fulfilled`, `set_requested`, `set_fulfilled` |
  | `robux` | Награды Robux | `robux_earned`, `robux_fulfilled` |
  | `games` | Игры: открытие и завершение заданий | `game_opened`, `game_completed` |

- Глаголы: watched «просмотр урока засчитан», passed «прошёл тест», failed «завершил тест», purchase «сделал покупку», wish_requested «просит выполнить желание», wish_fulfilled «желание выполнено», set_requested «собрал набор», set_fulfilled «получил пак для Roblox», robux_earned «выиграл Robux», robux_fulfilled «получил Robux», game_opened «открыл игру», game_completed «завершил игровое задание»; для остальных «новое событие».
- Отбираются отчёты, созданные после `device.created_at` и не старше 24 ч, если их категория включена у этого устройства и они ещё не отправлены. За один проход — до 5 на устройство. В тестовом режиме ничего не отправляется.
- Идемпотентность: `INSERT OR IGNORE parent_push_deliveries(owner,report_id,device_id)`. Перед отправкой проверка: устройство активно, роль parent, отчёт создан после подключения, категория включена (иначе `cancelled`). Topic `p` + 24 символа `sha256(report.id)`, TTL 86400. Тег уведомления `quest-parent-<reportId>`, поэтому события не заменяют друг друга. Неудачная отправка не повторяется.
- Триггеры: J4 (сразу после события) и J1 (каждый час — по всем владельцам с родительскими устройствами).
- Отчёты ребёнку никогда не уходят: проверка роли `parent` в запросе и в повторной проверке.

**Данные**: `parent_push_deliveries(owner, report_id, device_id, status, created_at)`, PK из 3 полей; удаление через 30 дней. `Report {id, created, lesson, kind, text, status, channels}`. Текст отчёта: «КвестКласс · имя\nурок\nдетали…\nВсего XP\nБаланс монет\nISO-время»; в push попадают строки `[2:-3]`.

**Внешние зависимости**: push. Telegram (`api.telegram.org/bot…/sendMessage`) и Resend (`api.resend.com/emails`) — параллельный канал отчётов из другого модуля.

### 2.7 Web Push: реализация транспорта

**Правила и логика** (`lib/web-push.ts`)
- Шифрование RFC 8291 `aes128gcm` на Web Crypto: эфемерный ECDH P-256, HKDF через HMAC-SHA-256 (`WebPush: info\0`, `Content-Encoding: aes128gcm\0`, `Content-Encoding: nonce\0`). Заголовок: salt 16 байт, rs = 4096, длина ключа 65 и сам ключ. Разделитель паддинга `0x02`. Открытый текст не больше 3993 байт. Тест сверяет результат с вектором из RFC 8291 Appendix A.
- VAPID (RFC 8292): JWT ES256, `aud` = origin endpoint, `exp = now + 12 ч`, `sub` = URL сайта (захардкожен). Заголовок `Authorization: vapid t=<jwt>, k=<public>`.
- Переменные окружения: `REMINDER_VAPID_PUBLIC_KEY` (публичный) и `REMINDER_VAPID_PRIVATE_JWK` (секрет). Пара должна оставаться той же между релизами.
- Отправка: `POST endpoint`, `redirect:'manual'` (любой 3xx — неуспех без деактивации), таймаут 12 с. Заголовки `TTL` (по умолчанию 1800), `Urgency` (`normal`), `Topic` (`quest-study-reminder`). `accepted = 2xx`, `expired = 404|410`.
- Белый список endpoint: только `https`, без порта, userinfo и hash; хост один из `fcm.googleapis.com`, `updates.push.services.mozilla.com`, `*.push.services.mozilla.com`, `web.push.apple.com`, `*.notify.windows.com`. Endpoint ≤2048 символов, `p256dh` — 65 байт с префиксом `0x04`, `auth` — 16 байт.
- Сводка Topic/TTL: напоминание `quest-study-reminder`/1800; серия `streak-<day>-<stage>`/до истечения; отчёт `p<hash24>`/86400; тест `quest-parent-test` или `quest-study-reminder`; мама `quest-mama-message`/900 (красный — `high`); похвала `quest-praise-<id18>`/86400; Стар `star-lesson-reminder`, `star-parent-report`/3600.
- «Принято push-сервисом» не означает «показано» — это явно сказано в UI.

**Внешние зависимости**: FCM, Mozilla autopush, Apple Web Push, WNS.

### 2.8 Service worker и PWA

**Что видит/делает пользователь**: в «Настройки и помощь» → «Звук и установка приложения» есть карточка `InstallApp`: иконка 48px, «КвестКласс на главном экране», кнопка «Установить» или «✓ Установлено». **Правила и логика** (`public/sw.js`, `app/pwa-registration.tsx`, `app/install-app.tsx`)

### 2.9 API нативных уведомлений (поллинг из APK)

**Правила и логика** (`lib/native-notifications.ts`, `lib/native-notification-model.ts`, `app/api/native-notifications/route.ts`)
- Регистрация: `POST`, нужна PIN-сессия, тело ≤3000 символов: `{id:'native:<uuid>', secret:<64 hex>, role, label ≤60, alerts}`. На сервере хранится только `secretHash = sha256(secret)`. Неактивные записи при каждой регистрации вычищаются.

- `nativeNotices` (максимум 20):
  - *родителю*: отчёты за 24 ч, созданные после подключения, по включённым категориям; `id = report:<id>`, заголовок «КвестКласс · <имя>», текст до 600 символов, `expiresAt = created + 24 ч`;

  - обычное напоминание отдаётся по тем же условиям, что и web: `dueReminder`, урок не начат, есть доступный урок без награды. `id = reminder:<day>:<HH:00>`, `expiresAt` = конец этого часа;

- Дедупликация делается **на клиенте**: множество `seen` до 1000 id. Сервер ленту не помечает.

**Данные**: в состоянии семьи `nativeDevices[]: {id, secretHash, role, label, alerts, active, createdAt}`; `NativeNotice {id, title, body, path, image?, expiresAt}`.

### 2.12 Распространение нативных релизов

**Правила и логика**
- Лента: `public/native-updates/releases.json` и её точная копия `lib/native-release-manifest.json`. Формат `{payload:"<JSON-строка>", signature:"<base64 RSA-SHA256>"}`. Внутри: `{schema:1, channels:{windows:{version, url, size, sha256, parts[{url,size,sha256}]}, android:{version, versionCode, url, size, sha256}}}`. Сейчас: Windows 2.0.2, 229 184 450 байт, 28 частей по 8 МиБ; Android 0.8, 1 408 719 байт.
- Сборка ленты (`scripts/package-native-release.py --windows-setup --android-apk --private-key`):

### 2.13 Загрузка картинок `/api/images` + R2 (общий для всего приложения)

**Правила и логика** (`app/api/images/route.ts`)
- `POST`: нужен аутентифицированный пользователь и PIN-сессия; запрос cross-site отклоняется. Тело — сырые байты; имя берётся из заголовка `X-File-Name` (URI-encoded, ≤100 символов).

  - Ответ `{image:'upload:<id>', asset}`.
- `GET ?id=`: курированные id перенаправляются (302) на статику; ассет должен принадлежать владельцу. Ответ: `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`, `CSP: default-src 'none'`.
- Кто пользуется: библиотека напоминаний (2.3); `ImagePicker` (`app/game-image.tsx`, группы `category|outfit|ticket|room`, клиент принимает исходник до 12 МБ и пережимает); `AnimationPicker` (`app/hero-animation.tsx`) в магазине, наборах, примерочной и категориях. Значение поля хранится как `upload:<id>`.

## 4. Чеклист паритета

### Расписание напоминаний
- [ ] Вкладки «МАМА!», «Расписание», «Картинки», «Телефоны»; по умолчанию открыта «МАМА!».
- [ ] По умолчанию: выключено, Пн–Пт, 11:00–15:00 (5 слотов), Калининград.
- [ ] Время слота — только целые часы 06:00–22:00; занятые часы в селекте недоступны; максимум 17 слотов; минимум 1 (у единственного слота корзина неактивна).
- [ ] «Добавить напоминание» ставит следующий свободный час после последнего слота.
- [ ] «Быстро заполнить»: «Начать в», «Каждый час/Каждые 2 часа», «Количество»; число слотов урезается так, чтобы последний был не позже 22:00.
- [ ] Сводка показывает дни, «Калининград», число напоминаний, статус «Включено/Выключено», список «время → название картинки», переключатель текстов.
- [ ] Индикатор несохранённых изменений и липкая панель «Сохранить расписание» (неактивна без изменений).
- [ ] Превью у слота: «Саша, пора делать уроки» + «Открой КвестКласс и начни урок.» + строка картинки.
- [ ] Сервер отклоняет другой часовой пояс, пустые дни, минуты ≠ 00, часы вне 6–22, повторяющееся время.
- [ ] Push уходит только в час слота, только в выбранные дни, только на телефоны с ролью ребёнка.
- [ ] Пропущенный час не досылается позже.
- [ ] Два параллельных запуска диспетчера дают одну отправку на устройство (ключ owner, день, час, устройство).
- [ ] Перестановка слотов или смена картинки после отправки не повторяет этот час.
- [ ] Старт видео или теста ставит паузу до конца дня; в UI видно «Сегодня урок уже начат…».
- [ ] Напоминание не уходит, если сегодня была активность по просмотру или попытка, даже если запись паузы не удалась.
- [ ] Напоминание не уходит, если нет доступных уроков без награды.
- [ ] В тестовом режиме напоминаний нет.
- [ ] TTL push 30 минут.
- [ ] Ответ push-сервиса 404/410 отключает устройство.
- [ ] `GET` диспетчера возвращает `lastRun` со счётчиками и временем, без персональных данных.
- [ ] Записи доставок старше 30 дней удаляются.

### Серия
- [ ] Предупреждения в 18:00 и 21:00 по Калининграду, ежедневно, независимо от дней расписания и паузы.
- [ ] Уходят только при серии ≥1 и несделанном сегодня (урок + тест); после сдачи теста не приходят.
- [ ] В часы 18–21 предупреждение о серии заменяет обычный слот.
- [ ] Картинка `star-streak.png`; просроченное предупреждение не показывается.
- [ ] Переключатель «Предупреждать об обнулении серии» отключает их.

### Картинки
- [ ] Библиотека: загруженные (новые первыми) → 62 встроенные курированные (15 эмоций мамы + 47 персонажей) → 5 готовых мам.
- [ ] Загрузка PNG/JPG/WebP ≤2 МБ; другие форматы и размеры дают понятную ошибку.
- [ ] ZIP ≤20 МБ, ≤100 картинок, ≤50 МБ после распаковки, папки поддерживаются, отчёт о пропущенных файлах с причинами, прогресс «i из n».
- [ ] Анимированный WebP отклоняется.
- [ ] Удаление спрашивает подтверждение; картинка исчезает из библиотеки и из случайного выбора; слоты с ней становятся «без картинки», время сохраняется; в играх и магазине картинка остаётся.
- [ ] «Перемешать и сохранить» меняет только картинки и тексты, время не трогает; повторов нет, пока не использована вся библиотека.
- [ ] Автосмена раз в 2 календарных дня, работает и при закрытом приложении; в UI видна дата следующей смены.
- [ ] Текст слота следует за выбранной картинкой (курированная → её фраза; эмоция мамы → её фраза или только инструкция; своя → только инструкция).
- [ ] Поиск по названию появляется, если картинок больше 6.

### Сообщение «МАМА!» и похвала
- [ ] Три уровня цвета; 15 эмоций с фильтрами «Все/Поддержать/Поторопить» и вариант «По цвету».
- [ ] Выбор урока (только доступные), текст до 160 символов, подсказанный текст позитивных эмоций не затирает текст родителя.
- [ ] «Посмотреть у себя» показывает карточку с меткой «Предпросмотр · только у тебя» и ничего не отправляет.
- [ ] Отправка неактивна без телефона ребёнка и в тестовом режиме.
- [ ] Повторная отправка того же сообщения доставляет только на телефоны, где прошлая попытка не удалась.
- [ ] Новое сообщение заменяет предыдущее; кулдаун 5 с; срок жизни 2 часа.
- [ ] Push «МАМА!» с картинкой эмоции; у красного высокий приоритет, `requireInteraction` и долгая вибрация; TTL 15 минут.
- [ ] В открытом приложении карточка появляется не позже чем через 15 с (сразу — по сообщению от SW), поверх игры, и ставит видео и озвучку на паузу.
- [ ] Красный уровень: маячок 🚨, пульсирующий ореол, короткая сирена (только при включённых звуках), кнопка «Послушать сигнал»; оранжевый: покачивание.
- [ ] Кнопка ▶ открывает выбранный урок (или следующий); закрытие помечает сообщение «закрыто»; у родителя отображается статус «Саша нажал открыть / закрыто / истекло / не подтверждено».
- [ ] Закрытое или открытое сообщение больше не показывается и убирается из шторки.
- [ ] Похвала: «ИДЕАЛЬНО!», «+N монет · +M опыта», кнопка ✓; дошлётся на заново подключённый телефон ребёнка.

### Телефоны и отчёты родителю
- [ ] Роли «Телефон Саши» и «Мой телефон», название до 60 символов, у родителя 5 категорий событий (по умолчанию все).
- [ ] Не больше 6 подключённых устройств; endpoint другого профиля отклоняется.
- [ ] Endpoint и ключи подписки не появляются в ответах API; на сервере подписка зашифрована.
- [ ] «Проверить уведомление» не чаще раза в 10 с; родитель может проверить «напоминание Саши» без смены роли.
- [ ] Родителю приходят только события после подключения, не старше 24 ч, только по выбранным категориям; ребёнку отчёты не приходят никогда.
- [ ] Заголовок отчёта «КвестКласс · <имя>: <глагол>»; разные события не заменяют друг друга в шторке.
- [ ] Отчёт приходит сразу после события и догоняется в ежечасном запуске; одно событие не приходит дважды.
- [ ] Нажатие на отчёт открывает PIN-гейт и затем «История и отчёты».
- [ ] Без поддержки push показывается сообщение про iPhone и домашний экран.

### Web Push / SW / PWA
- [ ] Шифрование совпадает с тестовым вектором RFC 8291 Appendix A; JWT VAPID живёт не больше 24 ч (в коде 12 ч), `aud` = origin push-сервиса.
- [ ] Принимаются только endpoint FCM, Mozilla, Apple, WNS по https; редирект считается ошибкой.
- [ ] SW не кэширует ничего; без сети навигация показывает «Подключись к интернету» с кнопкой «Попробовать снова»; `/api/*` и авторизацию SW не трогает.
- [ ] Manifest: «КвестКласс», standalone, `#101827`, иконки 192/512/maskable.
- [ ] Карточка «КвестКласс на главном экране»: «Установить» или инструкция для Chrome; в установленном режиме «Установлено».

### Android
- [ ] WebView на фиксированном HTTPS-origin; на своём домене нативный бар скрыт; меню из 5 пунктов.
- [ ] Регистрация из кабинета через `questclass://notifications`, системный запрос разрешения (Android 13+), на сервере хранится только хэш секрета.
- [ ] Фоновая проверка примерно раз в 15 мин и раз в минуту при открытом экране; одно уведомление не показывается дважды; уведомление само исчезает к `expiresAt`.
- [ ] Большая картинка в уведомлении берётся только с путей своего сайта.
- [ ] Значок меняется по часу Калининграда по 11 интервалам правил v4; после урока с тестом весь остаток дня «satisfied»; пока приложение на экране, значок не переключается.

### Windows
- [ ] Один установщик без прав администратора; ярлыки «Стар» и «КвестКласс»; автозапуск `--background`.
- [ ] Прозрачный оверлей поверх всех окон, клики проходят насквозь; скрывается, пока открыт урок или кабинет и при блокировке экрана.
