## 1. Обзор модуля

Ребёнок учится (видео + тест из 3 вопросов), выполняет задания родителя и играет в мини-игры. За это он получает **XP (опыт)** и **монеты**. XP только копится. От него считается **уровень** (300 XP на уровень), а каждый уровень даёт **Искру знаний** (гача-приз). Тот же XP параллельно заполняет выбранный **набор-альбом** с 5 наклейками-этапами. Монеты тратятся в **Магазине желаний** на героев, комнаты и билеты (реальные желания и Robux). Билеты выдаёт родитель по просьбе ребёнка. **Ачивки** дают по 1 Искре. Сезонный **Хэллоуин** добавляет ловлю призраков за монеты. Мини-игры — три **внешних сайта** в iframe. Они сообщают о завершённых заданиях, а сервер начисляет монеты и XP с дневным лимитом. Родитель (вход по PIN) управляет причинами наград, начислениями и отменами, каталогом магазина, наборами, призами Искр, доступом к играм и наградами за игры.

### Поток валют

```
ИСТОЧНИКИ                                   БАЛАНСЫ                       ПОТРЕБИТЕЛИ
─────────                                   ───────                       ───────────
Тест урока (1 раз на урок) ─┐
  XP = floor(xp·score/3), монеты = coins при score≥1
Ручное начисление родителя ─┤
  (причины: посещение, домашка, своё)        ┌─► XP (только растёт;   ─► Уровень = floor(XP/300)+1
Игровое событие (лимит/день) ┤               │   падает при отмене)       └─► Искра за каждый уровень
Серия 5 дней: +200м +200XP +3 искры ─────────┤                          ─► Набор-альбом (XP распределяется,
Обучение: +100м +120XP +1 искра ─────────────┤                              не тратится): 5 наклеек → скины/фоны
Похвала мамы (разовая) ──────────────────────┤                              → «пак Roblox» по запросу
Призрак Хэллоуина: +5 монет ─────────────────┼─► МОНЕТЫ = Σ доходов   ─► Магазин: герой / комната / билет
Искра без новых вещей: +30/75/200 монет ─────┘   − Σ цен покупок            (покупка = снимок, не возвращается)
                                                 (может уйти в минус)       Билет ─► «Хочу использовать» ─► родитель выдал
Ачивка: +1 искра ─┐                                                          Robux ─► частичная выдача родителем (FIFO)
Подарок родителя: +N искр (обычные/золотые) ┼─► ИСКРЫ = уровень + подарки + серии − открытые − корректировки
Первая серия: +1 искра (особый подарок Астро)┘                ─► открытие: скины/комнаты (покупка за 0) + бонус Robux / билет картошки / монеты
```

## 2. Фичи

### 2.1. Валюты, баланс, уровень, счётчики

**Что видит/делает пользователь**
- Ребёнок: в шапке главного экрана раскрывающаяся панель «Уровень / Опыт / Монеты / Искры» (`app/experience-disclosure.tsx`). Там подсказки «XP — опыт: приближает наклейки и новый уровень», «Монеты: можно потратить в магазине», «Искры: подарок за новый уровень». В других вариантах экрана это полоса `ExperienceBar` (`app/knowledge-sparks.tsx`): «Уровень N», «X XP всего», монеты, прогресс «levelXp / 300 XP · до уровня N+1» и кнопка искры («Искры знаний · N», «Забрать награду», «Ещё K XP до Искры»).
- В Хэллоуин слово «XP» в детском интерфейсе заменяется на «конфеты» (`app/halloween-art.tsx#XpIcon`, `games-menu.tsx`, `use-game-rewards.ts`).
- Диалог «Мои награды» показывает «N монет · M XP · K миссий» и аккордеон «История наград и занятий» (`app/focus-app.tsx`, словарь `historyLabel`).

**Правила и логика** (`lib/game.ts#gameTotals`, `lib/knowledge-sparks.ts#balances`)
- **XP** = Σ `rewards[lessonId].xp` (награды за тесты) + Σ `activities[].xp`, где `cancelledAt` не задан.
- **Монеты** = Σ `rewards[].coins` + Σ `activities[].coins` (без отменённых) + Σ `sparks.draws[].coins` − Σ `purchases[].price`. В `purchases` попадают все покупки, включая призы Искр за 0 монет. Баланс **может быть отрицательным** (после отмены начисления или пересдачи с мамой). Тогда покупки блокируются (`buyItem`: «Пока не хватает монет»).
- В `activities` попадают все «прочие» доходы: ручные начисления, игры (`reasonId:'game-play'`), призраки (`'halloween-ghost'`), серия (`'lesson-streak'`), обучение (`'first-quest'`), похвалы (`'__custom'`), тестовое начисление (`'test-mode'`). Поэтому формула баланса единая.
- **Уровень** = floor(max(0,XP)/300)+1; `levelXp` = XP mod 300; `XP_PER_LEVEL=300` (`lib/knowledge-sparks.ts`).
- **Миссии** = количество уроков с полученной наградой (`childState.completed`).
- Покупки и выданные подарки не возвращают монеты (`lib/reward-inventory.ts#fulfillReward`, комментарий). Отмена начисления уменьшает XP и монеты.
- Экономические константы (`lib/economy-settings.ts`, «согласованный баланс ноября 2026»): монеты за урок 350, монеты за игровое задание 30, лимит игровых наград 3 в день, цены магазина (см. 2.5).
- Часовой пояс семьи жёстко задан как UTC+2 (Калининград) для «дня» серий, игр, ачивок и сезона (`lesson-streak.ts#lessonDay`, `play-rewards.ts#rewardDay`, `halloween.ts`).

**Данные**
- По ученику: `LessonReward{lessonId, xp, coins, at}`, `Activity` (2.3), `Purchase` (2.5), `SparkDraw.coins` (2.10).
- Производные (не хранятся): `xp`, `coins`, `level`, `levelXp`, `completed`.

**Экраны и визуал**: `app/experience-disclosure.tsx`, `app/knowledge-sparks.tsx#ExperienceBar`, CSS `knowledge-sparks.css`, `lesson-refresh.css`. Иконки lucide `Coins`, `Zap`, `Sparkles`; искра — `/game/sparks/knowledge-spark.webp`.

### 2.2. Награда за урок (тест)

**Что видит/делает**: после видео ребёнок отвечает на 3 вопроса. При ≥1 верном ответе появляется «Миссия выполнена!» и анимация пополнения набора (2.9). Потом окно выбора игры (2.12) и, если вырос уровень, панель нового уровня (2.10). При 0/3 появляется сообщение «Награда не начислена. Нужно повторить тест».

**Правила** (`lib/quest-model.ts#lessonTestReward`, `#answerAttempt`)
- Тест пройден, если score ≥ 1. Награда: XP = floor(lesson.xp × score/3), монеты = lesson.coins целиком (при score ≥ 1).
- Награда выдаётся **один раз на урок** (`rewards[lessonId]`). Повторные попытки после прохождения запрещены.
- Значения по умолчанию для урока: xp 100, coins 350 (`lib/curriculum.ts#mergeVideos`, `DEFAULT_LESSON_COINS`). Диапазоны редактирования: xp 1–1000, coins 0–1000.
- Родитель может массово задать XP и/или монеты для **всех** уроков, включая черновики (`route: setAllLessonRewards`, UI `app/parent-lesson-rewards.tsx` «Награды за все уроки»).
- «Пройти с мамой» (`restartWithMom`, PIN в запросе) **снимает** прежнюю награду урока (XP и монеты). Тест начинается заново, в режиме `momMode`.
- Каждое завершение создаёт отчёт `passed`/`failed`, который уходит родителю в Telegram/email и push.

**Данные**: `Lesson.xp`, `Lesson.coins` (каталог уроков — модуль 01). Состояние: `LessonReward`, `Attempt.reward`.

**Экраны**: `focus-app.tsx` (экран результата, `CollectionGain`), `parent-lesson-rewards.tsx`.

### 2.3. Ручные награды родителя: причины, начисления, отмена; похвала

**Что видит/делает**
- Родитель: Кабинет → «Награды» → «Монеты и опыт» (`app/parent-activities.tsx#ParentActivities`). Наверху блок «Награды за все уроки». Ниже форма «Начислить награду»: «За что» (список причин + «Своя награда»), «Опыт · XP», «Монеты», «Дата, предмет и урок» (дата, предмет или «Без предмета», «Урок из списка» / «Не привязывать к уроку»), название. Есть «Изменить готовые награды» (добавить, переименовать, убрать причину) и список начислений с кнопкой «Отменить начисление». Отменённые помечены «Отменено». Тосты: «Начислено N XP и M монет.», «Начисление отменено. Баланс пересчитан.»
- Ребёнок: видит начисления в истории наград. Похвалы показаны на вкладке «От мамы» диалога наград: «ОТ МАМЫ С ЛЮБОВЬЮ», «Мама тобой гордится», кнопка «Спасибо, мам!» (`app/achievements.tsx#RewardsCollection`).

**Правила**
- Причины (`lib/game.ts#saveRewardReason`, `#archiveRewardReason`). По умолчанию две: «Присутствие на уроке» (id `attendance`, 50 XP / 10 монет) и «Домашняя работа» (id `homework`, 50 XP / 10 монет). Имя 1–60 символов, уникально среди неархивных (без учёта регистра и повторных пробелов). XP 0–1000, монеты 0–1000, хотя бы одно больше 0. Не более 100 причин. Удаление — это архивирование, история сохраняется. Для новой «Своей награды» UI подставляет 50 XP / 10 монет.
- Начисление (`lib/game.ts#grantActivity`). Поля: `requestId` (uuid, идемпотентность: повтор возвращает прежнюю запись), `reasonId` (существующая неархивная причина или `__custom` → «Своя награда»), `date` (YYYY-MM-DD, валидная), `categoryId` (существующий предмет или пусто → «Без предмета»), `title` 1–150, XP 0–1000, монеты 0–1000, хотя бы одно больше 0.
- Защита от дублей: нельзя второй раз выдать награду с той же причиной, датой, предметом и нормализованным названием среди неотменённых начислений («За это занятие или задание награда уже выдана…»). Исключение — тестовый режим.
- В начислении сохраняются снимки `reasonName` и `categoryName`. Переименование причины историю не меняет. Лимит истории — 3000 записей.
- Отмена (`#cancelActivity`) идемпотентна: ставит `cancelledAt` и не удаляет запись. XP снимается из наборов по записанному источнику (2.9). Создаётся отчёт `reward_cancelled` («−X XP и −Y монет»), он только записывается в историю и не рассылается.
- Начисление создаёт отчёт с видом причины («… Подтверждено родителем. Начислено X XP и Y монет.»), который отправляется родителю.
- Похвала мамы (`lib/parent-praise.ts`) — это сообщение `MomMessage{kind:'praise', text, image, stars, xp, coins, expiresAt=+30 дней}` плюс начисление через `grantActivity` и web-push ребёнку «⭐⭐⭐⭐⭐ Идеально! … +50 монет · +50 опыта». В исходнике **нет общего UI** создания похвалы: есть только жёстко прошитые разовые награды (см. «Не переносить»). В новом продукте это должна быть обычная функция родителя.
- Тестовое начисление (`route: testGrant`) работает только в тестовом режиме: причина «Проверка опыта», XP 1–1000 (задаётся), 100 монет.

**Данные**
- Каталог (на родителя/семью): `RewardReason{id, name, xp, coins, archived}`.
- По ученику: `Activity{id, requestId, kind:'attendance'|'homework'|'custom', reasonId, reasonName, date, categoryId, categoryName, title, xp, coins, sparks?, at, cancelledAt?}`; `ParentPraise{id, text, image, stars, xp, coins, createdAt, expiresAt, openedAt?, dismissedAt?, push?}`.

**Экраны**: `parent-activities.tsx` + `parent-activities.css`, `parent-lesson-rewards.tsx`, `achievements.tsx#RewardsCollection`, картинка похвалы `public/rewards/towel-perfect-five-stars.png`.

### 2.4. Бонусы-источники вне магазина

**Правила**
- **Серия занятий** (`lib/lesson-streak.ts#syncLessonStreak`). День засчитывается, если в этот день (UTC+2) завершён тест (с любым результатом, не заменённый пересдачей) по просмотренному уроку. На каждом 5-м дне подряд начисляется `STREAK_REWARD = {5 дней, 200 монет, 200 XP, 3 искры}` как активность `requestId='lesson-streak:<день>'` (идемпотентно), плюс отчёт `lesson_streak`. После закрытого 5-дневного цикла следующий день начинается с 0. Игры не учитываются. Празднование: видео `public/celebrations/streak-five-v1.mp4` и постер `streak-five-poster.webp` (`app/streak-celebration.tsx`, показ один раз, флаг в localStorage). Карточка серии в шапке — модуль уроков.
- **Первое обучение** (`lib/child-tutorial.ts`): `TUTORIAL_REWARD = {120 XP, 100 монет, 1 искра}`, разово (активность `first-quest`, подарок искры).
- **Первая серия** (`lib/first-streak-achievement.ts`): при первой серии в 5 дней — ачивка «Пять дней подряд!» и 1 искра с особым подарком «Лунный подарок Астро» (см. 2.10–2.11).

### 2.5. Магазин желаний (ребёнок)

**Что видит/делает** (`app/game-panels.tsx#ShopPanel` в режиме `focused`, `FocusedShopCard`)
- Заголовок «Магазин желаний», плашка баланса «N монет», подпись «За монеты: персонажи, комнаты, Robux и желания.», кнопка чтения вслух страницы.
- Фильтры (`app/shop-category-filters.tsx`): «Всё / Герои / Комнаты / Желания». Под «Герои» — «Все персонажи / Обычные / Анимированные». Под «Комнаты» — «Все комнаты / День / Ночь / Специальные / Анимированные» с подсказкой «Комнату можно менять отдельно от персонажа. Покупка остаётся у тебя.». Категории различаются иконкой, подписью, цветом и галочкой выбора. Комнаты: день — солнце, ночь — луна, специальные — искры, анимированные — хлопушка.
- Сетка карточек. В карточке: превью (герой или комната; у живых кнопка «плей»), кнопка «Послушать», символ раздела комнаты, метка анимации, название-кнопка (открывает «Подробнее» с описанием, ценой и «Понятно»), кнопка цены. Если монет не хватает, кнопка неактивна и показывает «Ещё N монет».
- **Уже купленное в фокус-магазине скрыто.** Сортировка: подсвеченный в обучении товар первым, затем живые (анимированные) раньше статичных.
- Подтверждение: «Забираем персонажа/комнату/билет?», крупное изображение, описание, «Потратишь N монет. Останется M.», «Подтвердить покупку» / «Пока не покупать».
- Тосты после покупки: «Новый образ в твоём гардеробе!», «Новая комната! Выбери её в разделе «Герой → Комнаты».», «Билет сохранён в «Мои желания»!». После покупки билета сразу открывается «Мои желания».
- Пустой список: «Здесь пока нет новых покупок. Загляни в другую категорию.»

**Правила** (`lib/game.ts#buyItem`, `lib/shop-prices.ts`)
- Типы товаров: `outfit` (образ героя, опционально `animation` → «живой»), `room` (фон комнаты с `roomCategory` day|night|special, анимированная, если есть движение), `ticket` (билет: `rewardType` wish|robux, `rewardAmount`).
- **Цены по умолчанию** (`SHOP_PRICES`, применяются ко всему встроенному каталогу): обычный герой 40, живой герой 80, комната 120, анимированная комната 200, «300 Robux» 300 (выдаёт 300 Robux), «Картошка и наггетсы из Додо» 400 (wish ×1). Остальные билеты сохраняют исходную цену: «Семейный киновечер» 100, «Сюрприз» 200. Анимированной считается комната с `animation`, «Ночной отель» или комната с ambient-темой (`room-assets.ts#hasRoomMotion`).
- Видимость по умолчанию: включены базовые герои, паки персонажей, 31 комната, «Ночной отель», 9 «экшен»-анимаций и билет «300 Robux». Скрыты (`active:false`, остаются призами альбомов и Искр): паки Mart/Cadence/Dozer/Rebound/Astro, live-sets (вампир/фея/сик), билеты картошки, кино и сюрприза. Это видно по коду. Живые данные семьи не проверены.
- Покупка идемпотентна по `requestId` (uuid, генерируется при открытии диалога). Повтор возвращает ту же покупку, другой `itemId` с тем же `requestId` даёт ошибку.
- Проверки: товар активен; `version` совпадает (иначе «Родитель изменил товар. Обнови магазин…»); герой или комната ещё не принадлежат ребёнку (включая полученные из альбома и визуальные дубли с тем же image+animation, `ownedShopItem`); монет ≥ цены; покупок меньше 3000. **Билеты можно покупать многократно.**
- Покупка — это **снимок** товара (title, description, price, image, animation, roomCategory, rewardType/Amount). Последующие правки каталога её не меняют.
- Отчёт `purchase` отправляется родителю («Покупка: N монет. Образ добавлен в гардероб / Комната добавлена… / Билет сохранён…»).

**Данные**
- Каталог: `ShopItem{id, kind, title≤100, description≤800, price 0–100000, image, animation?, roomCategory?, rewardType?, rewardAmount?, active, version}`.
- По ученику: `Purchase{id, requestId, itemId, kind, title, description, price, image, animation?, roomCategory?, rewardType?, rewardAmount?, redeemedAmount?, source?:'spark', at, status:'ready'|'requested'|'fulfilled', requestedAt?, fulfilledAt?}`.

**Экраны и визуал**: `game-panels.tsx` (ShopPanel, FocusedShopCard), `shop-category-filters.tsx` + `.css`, `shop-artwork-gate.tsx` (ленивая загрузка, приоритет первым 4), `room-artwork.tsx`, `hero-animation.tsx#HeroArtwork`, `reference-icons.tsx#ShopBagIcon` (иконка вкладки). Стили карточек разбросаны по `focus-style.css`, `focus-theme.css`, `mockup-home.css`, `rooms.css`, `mobile-refinement.css`, `desktop-layout.css`. Билеты рисуются из спрайта `public/game/wishes.png` / `wishes-transparent-v1.png` (2×2: fries, tokens, cinema, gift). Robux — `app/robux-icon.tsx`, `public/game/report-robux.svg`.

### 2.6. Билеты желаний и инвентарь Robux

**Что видит/делает**
- Ребёнок: «Мои желания» (быстрое меню, ярлык в шапке, вкладка «Билетики» диалога наград; `app/reward-panels.tsx#WishInventory`). Показываются группы оставшихся наград: картинка, название, остаток («Билетов: N» / «N Robux»), описание. Статусы: «Куплено · можно использовать», «Просьба отправлена», «Родитель получил твою просьбу». Кнопка «Хочу использовать». Внизу «История» полученного: «Выданы родителем», дата, «Показать ещё» по 20. Пусто: «Пока нет неиспользованных наград. Новые билетики можно купить в магазине.»
- Родитель: Кабинет → «Награды» → «Выдать желания» (`RewardFulfillment`). Список «Ждут выполнения». Для Robux: «Сколько Robux уже выдано?», поле количества, «Сейчас осталось: N», «После отметки: M», «Подтвердить выдачу». Для желаний: «Желание уже выполнено?» → «Подтвердить выполнение». Пояснения: «Учебные монеты уже списаны при покупке…», «Укажите только уже переданные ребёнку Robux. Приложение сохраняет отметку, сам перевод вы делаете отдельно.»

**Правила** (`lib/reward-inventory.ts`)
- Группировка: все Robux-билеты образуют одну группу `robux` (суммируются, включая Robux из Искр). Желания группируются по [itemId, title, description].
- `remaining(purchase)` = rewardAmount − redeemedAmount (0 для выданных и не-билетов).
- `requestReward(groupKey)`: все `ready`-покупки группы переходят в `requested` (не идемпотентно по requestId, но повтор безвреден). Отчёт `wish_requested` отправляется родителю.
- `fulfillReward{requestId, groupKey, amount, expectedRemaining}`: идемпотентно по `requestId`. `expectedRemaining` должен совпасть с текущим остатком (оптимистичная проверка). amount в пределах 1..remaining. Списание идёт **FIFO по времени покупки** (частичная выдача возможна). Покупка становится `fulfilled`, когда выдана целиком. Создаётся квитанция `RewardReceipt` (лимит 5000). Отчёты `robux_fulfilled` / `wish_fulfilled`.
- Устаревший поштучный поток: `requestTicket(purchaseId)` (ready → requested, идемпотентно) и `fulfillTicket(purchaseId)` (только из requested; создаёт квитанцию `ticket:<id>`).
- Тип награды билета определяется так (`ticketReward`): явный `rewardType`. Для старых записей Robux распознаётся только по названию вида «300 Robux». **Цена в монетах никогда не означает количество Robux.**

**Данные**: `RewardReceipt{id, requestId, groupKey, rewardType, title, image, amount, at, allocations[{purchaseId, amount}]}`. `RewardGroup` — производная.

**Экраны**: `reward-panels.tsx`, `quick-menu.tsx` («Мои желания»), ярлык `wishes-fries-shortcut` в `experience-disclosure.tsx`.

XP при этом не тратится: общий XP и монеты не меняются.

- Награды этапов: `rewardItems` (4–5 элементов): `'__cover'` = скин с обложки, `''` = только наклейка, иначе id не-билетного товара каталога (может быть скрыт в магазине). Пятая наклейка тоже может давать награду. Награды по умолчанию прошиты по картинке набора (`defaultCollectionRewards`).
- Roblox-пак: `requestCollection` (только собранный, идемпотентно; отчёт `set_requested` родителю) → `fulfillCollection` (родитель, только после просьбы; отчёт `set_fulfilled`).
- `saveCollection`: title 1–60, goalXp 100–100000, обложка — встроенный герой или загруженная статичная картинка, rewardItems 4–5. Ссылка Roblox только https на `roblox.com`, `www.roblox.com`, `create.roblox.com`. Не более 50 наборов. Цель собранного набора менять нельзя. Цель не может быть ниже уже набранного XP. Уже выданную награду этапа менять нельзя.
- ZIP (`app/api/collection-pack/route.ts`): POST только с родительской сессией, файл `.zip`, ≤30 МиБ, сигнатура `PK\x03\x04`, хранилище R2 `collection-packs/<sha256(owner)>/<uuid>`. Если сохранить состояние не удалось, объект удаляется. GET: ребёнок скачивает только после сборки набора, родитель — всегда. Заголовки `attachment`, `nosniff`, `no-store`, CSP `default-src 'none'`. Содержимое не исполняется и не валидируется на совместимость с Roblox.

**Правила** (`lib/knowledge-sparks.ts`)
- Баланс искр: **уровневые** = floor(XP/300) − открытые уровневые − снятые; **подарочные** = Σ подарков без gold + Σ `activity.sparks` у серий − открытые подарочные − снятые; **золотые** = Σ gold-подарков − открытые золотые − снятые. Списание идёт в порядке gold → gift → level. `available` = сумма. На кнопке показывается `available + (есть неувиденный приз ? 1 : 0)`.
- Источники подарочных искр: подарок родителя `giftSparks{requestId, amount 1–20, gold}` (идемпотентно, ≤1000 подарков), каждая ачивка (+1), первое обучение (+1), серия 5 дней (+3), первая серия (+1 с особым подарком).
- **Колода редкостей**: 10 карт [3★×6, 4★×3, 5★×1], перемешивается криптослучайно. Когда колода пуста, создаётся новая. **Гарант**: если `sinceGold ≥ 9`, выпадает 5★. Счётчик сбрасывается на 5★ и растёт на остальных. `toGuaranteed = max(1, 10 − sinceGold)`. Золотая искра всегда даёт 5★ и не трогает колоду и счётчик.
- Пул призов: включённые призы, все `itemIds` которых есть в каталоге как не-билеты (скрытые в магазине тоже подходят). Кандидаты — призы выпавшей редкости. «Свежий» приз должен содержать хотя бы одну **ещё не принадлежащую** вещь (сравнение по image+animation; стартовые герои и комната считаются принадлежащими) или иметь Robux < 1000.
- Нет кандидатов этой редкости → ошибка «Родителю нужно включить хотя бы одну награду на N звёзд. Искра сохранена.» Все кандидаты исчерпаны → **монеты**: 3★ = 30, 4★ = 75, 5★ = 200.
- Ручной выбор родителя (`chooseNextSpark`) применяется к следующему открытию, если приз ещё может что-то дать. Он **не понижает** гарантированную или золотую 5★ (тогда приз отложен). Расходуется при использовании.
- Запланированные Robux (`planSparkRobux` 0–1000) добавляются к следующему открытию вместо случайного бонуса и расходуются.
- **Случайный бонус** (только без ручного приза и без запланированных Robux), бросок 0–99: 3★ — 8% → 50 Robux; 4★ — 7% → 100 Robux, 3% → 250 Robux, 8% → билет на картошку; 5★ — 10% → 500 Robux, 1% → 1000 Robux, 15% → билет на картошку. Приз с Robux = 1000 разыгрывается автоматически без этой суммы: 1000 Robux даёт только ручной выбор.
- Выдача: каждая новая вещь записывается как `Purchase{price:0, source:'spark', status:'ready'}`. Robux — как билет-покупка `rewardType:'robux'` (попадает в инвентарь Robux, 2.6). Картошка — как билет wish ×1. Лимиты: открытий ≤3000, покупок ≤3000.
- **Надёжность**: результат сохраняется до анимации. Повтор с тем же `requestId` возвращает тот же приз. Пока предыдущий приз не подтверждён (`acknowledgeSpark` → `seen`), новое открытие возвращает его же («Забрать награду»). Искра никогда не сгорает при сбое.
- Начальный список призов (создаётся один раз): каждая не-билетная вещь каталога — отдельный приз. Редкость 4★, если это живой герой или комната с движением, иначе 3★. Комплекты 5★: «Хранитель времени» (cadence-live + обсерватория), «Мир Марта» (mart-live + острова), «Сонное королевство» (dozer-boy-live + спальня). Выключенные комплекты: «Живой герой + 100 Robux» (4★) и «Мир Cadence + 1000 Robux» (5★). Новые товары в пул сами не попадают: `addSparkPrize` (≤300 призов). `saveSparkPrize` меняет вкл/выкл, редкость и Robux.
- Особый подарок первой серии (`ASTRO_GIFT`): «Лунный подарок Астро» 5★ = живой Астро + «Лунная комната Астро» + 500 Robux. Выдаётся отдельно от колоды, override и счётчика.
- Отчёт `robux_earned` при выигрыше Robux («…родитель поможет получить Robux в Roblox»).

**Данные**
- Конфиг (каталог, редактируемый): `SparkConfig{xpPerLevel:300, deck:[3×6,4×3,5×1], pityAfter:9, coinFallback{3:30,4:75,5:200}, bonuses{rarity→[{chancePct, reward:robux|'fries'}]}, maxRobux:1000}`; `SparkPrize{id, title, rarity 3|4|5, enabled, itemIds[], robux}`.
- По ученику: `SparkState{deck[], sinceGold, nextPrizeId?, nextRobux?, gifts[{requestId, amount, gold}], draws[SparkDraw], adjustments[{requestId, at, level, gift, gold, reversedAt?}]}`; `SparkDraw{id, requestId, source:'level'|'gift'|'gold', prizeId, rarity, title, items[], friesTicket?, robux, coins, at, seen?}`.

**Правила** (`lib/play-rewards.ts`)
- Реестр игр: `handwriting` «Волшебные прописи», `hotel` «Вечный Хэллоуин», `multiplication` «Лес чудес». У каждой: url внешнего сайта, обложка `/game/menu/*.webp`, подпись задания.

- `startGame(gameId)`: проверяет доступ (2.13), создаёт сессию на **2 часа** со снимком текущих coins/xp, хранит последние 20 сессий, отмечает запуск для ачивок. Отчёт `game_opened` пишется не чаще раза в минуту на игру. Само открытие ничего не начисляет.
- `gameReward{sessionId, gameId, eventId(1–120), testMode}`:
  - если `(session, event, game)` уже начислено, возвращается `credited` с прежними суммами без изменений (идемпотентность);
  - сессия должна существовать и не истечь, иначе ошибка «Игровая сессия закончилась…»;
  - событие отмечается в сессии (≤200 событий) и **засчитывается для ачивок даже при исчерпанном лимите**;
  - если `remaining = 0` или обе суммы 0, ответ `limit` без начисления;
  - иначе coins = min(снимок сессии, текущие настройки), так же XP. Создаётся grant (дневной учёт, хранится 3 дня) и активность `reasonId:'game-play'`, title = название игры. Ответ `credited`.
  - отмена такой активности родителем **не возвращает** дневной лимит.
  - режим (live/test) должен совпадать с режимом приложения.
- **Контракт с внешней игрой** (игры — отдельные сайты, в репозиторий не входят):
  1. Запуск: `GET <gameUrl>?questOrigin=<origin КвестКласса>&questGame=<id>&questMode=live|test&questSession=<uuid>` в iframe (`allow="autoplay; fullscreen; encrypted-media; gamepad"`). Перед запросом сессии выполняется запрос Fullscreen API.
  2. Игра → родитель (postMessage на точный `questOrigin`): `{type:'questclass:complete', gameId, sessionId, eventId}` на каждое завершённое задание; `{type:'questclass:return', gameId, sessionId, pending:[{gameId, sessionId, eventId}]≤20}` при возврате. Родитель принимает сообщение, только если совпадают точный origin игры, окно-источник (contentWindow), gameId и sessionId.
  3. Родитель → игра: `{type:'questclass:reward', sessionId, eventId, status:'credited'|'limit', coins, xp, remaining}` после сохранения; `{type:'questclass:request-return'}` при нажатии «КвестКласс» (ответа ждёт 1 с, затем закрывает сам). Закрытие ждёт незавершённые начисления не дольше 1,5 с.
  4. Прямая доставка без родителя: `POST /api/game-reward`, `Content-Type: text/plain` (простой CORS-запрос с `credentials:'include'`), тело JSON ≤2000 байт `{sessionId, gameId, eventId, testMode}`. Origin обязан точно совпасть с url этой игры. CORS разрешён только этим origin. Пользователь определяется авторизацией платформы.
  5. Резервный возврат: `?questReturn=<JSON-массив ≤20 событий>` в URL КвестКласса. После успешного начисления параметр удаляется.
  6. Игра держит очередь неотправленных событий (localStorage/sessionStorage) и повторяет отправку (online, таймер, следующий запуск). Сервер начисляет каждое событие один раз.
- Пока игра открыта, клиент перепроверяет доступ каждые 15 с и при фокусе. Если доступ закрыт, игра закрывается с сообщением «Доступ к игре закрыт…».

**Данные**
- Каталог: `QuestGame{id, title, image, url(origin), taskLabel, achievementId?}`.
- По ученику: `PlaySettings{enabled, coins, xp, dailyLimit}`, `PlaySession{id, gameId, at, expires, coins, xp, events[]}`, `PlayGrant{sessionId, eventId, gameId, day, at, coins, xp}`.

**Правила** (`lib/game-access.ts`)
- Замок-ожидание `lockGamesUntilLesson`: запоминает `blockedAt` и список уже просмотренных уроков, снимает индивидуальные «открыто» (оставляет «закрыто»). Снимается автоматически, когда **досмотрен новый урок** (`watch.done`, `completedAt ≥ blockedAt`, урока нет в списке). Тест не нужен.
- Индивидуальное переопределение: `false` закрывает игру даже после урока (причина `parent`), `true` открывает даже при ожидании. `all` устанавливает всем. «Открыть все» также снимает замок.
- В тестовом режиме все ограничения игнорируются.
- Игра закрыта, если есть причина `parent` или `lesson`. `requireGameAccess` проверяется в `startGame`.

**Данные**: по ученику `GameAccess{overrides{gameId→bool}, lock?{id, blockedAt, completedBefore[], releasedAt?, lessonId?}}`.

## 4. Как сделать универсальным (admin → learners)

- **Учёт как журнал**: одна таблица `ledger_entry{learnerId, currency: xp|coins|sparks|external(Robux…), amount ±, sourceType, sourceId, requestId UNIQUE, at, reversedBy?}`. Баланс = сумма. Отмена — это сторнирующая запись. Покупка — отрицательная запись в монетах. Идемпотентность обеспечивает уникальный `(learnerId, requestId)`.
- **Источники наград как типы**: `lesson_test`, `manual_grant(reasonId)`, `game_event(gameId)`, `streak_bonus`, `tutorial`, `seasonal_event`, `spark_fallback`, `achievement`, `praise`. Правила начисления (суммы, лимиты в день, таймзона) — настройки на уровне админа или ученика.
- **Причины наград = задания/обязанности**: каталог админа (имя, XP, монеты, иконка, повторяемость, лимит «раз в день/на предмет»), доступный всем ученикам или выбранным. Похвала — тот же manual_grant с текстом, картинкой, звёздами и push.
- **Виды товаров**: `cosmetic` (слоты: персонаж, комната; можно добавлять новые слоты), `wish` (реальное желание с процессом «просьба → выполнено»), `voucher` (внешняя валюта с единицей и количеством; Robux как частный случай; частичная выдача FIFO). Цена и видимость задаются глобально с переопределением на ученика.
- **Каталоги редактирует админ, а не копирует каждая семья**: персонажи (арт, footOffset, связанные анимации), анимации, комнаты (категория, точка опоры, ambient-тема, слои/события/звуки), наборы-альбомы (тема, наклейки, награды этапов, цель XP), призы Искр, ачивки, игры, сезоны. В состоянии ученика хранятся только ссылки на каталог и снимки покупок.
- **Гача как конфиг**: состав колоды, порог гаранта, таблица бонусов, монеты при исчерпании, XP на уровень. Пул призов строится из каталога динамически (флаг «участвует в Искрах»).
- **Ачивки как правила над событиями** (тип события, фильтр, окно, цель), а не захардкоженный `evidence()`. Эпоха и перезапуск — на ученика.
- **Игры — реестр интеграций**: id, origin, url запуска, подпись задания, связанная ачивка, награды по умолчанию. Контракт postMessage и `POST /game-reward` общий и версионированный.
- **Таймзона и имя** берутся из профиля ученика или семьи, а не UTC+2 и «Саша».

## 5. Чеклист паритета

### Валюты и баланс
- [ ] Монеты = доходы (тесты + неотменённые начисления + монеты Искр) − Σ цен покупок; значение может быть отрицательным.
- [ ] XP = тесты + неотменённые начисления; Искры не дают XP; отмена уменьшает XP и монеты.
- [ ] Уровень = floor(XP/300)+1; полоса «levelXp / 300 XP · до уровня N+1».
- [ ] Шапка ребёнка: раскрывающаяся панель «Уровень / Опыт / Монеты / Искры» с пояснениями.
- [ ] В Хэллоуин XP в детском интерфейсе называется «конфеты».
- [ ] Отрицательный баланс блокирует покупки с текстом «Пока не хватает монет…».
- [ ] День для серий, игр и ачивок считается по таймзоне семьи (сейчас UTC+2).

### Награда за урок
- [ ] Тест пройден при ≥1 верном; XP = floor(xp·score/3), монеты = coins целиком.
- [ ] Награда за урок выдаётся один раз; дефолт 100 XP / 350 монет.
- [ ] «Награды за все уроки»: массово XP (1–1000) и/или монеты (0–1000), включая черновики.
- [ ] «Пройти с мамой» снимает прежнюю награду урока.

### Ручные начисления
- [ ] Две причины по умолчанию: «Присутствие на уроке» и «Домашняя работа», по 50 XP / 10 монет.
- [ ] Причины: создать, переименовать, архивировать; имя уникально без учёта регистра; ≤100 причин; XP/монеты 0–1000, не оба нуля.
- [ ] Форма начисления: причина или «Своя награда», XP, монеты, дата, предмет, урок, название.
- [ ] Повторный запрос с тем же requestId не создаёт второе начисление.
- [ ] Дубль (та же причина, дата, предмет и название) отклоняется понятной ошибкой.
- [ ] Отмена начисления идемпотентна, запись остаётся с пометкой «Отменено», баланс пересчитан.
- [ ] Отмена снимает XP из того набора, куда он попал, даже после смены набора.
- [ ] Похвала мамы: текст, картинка, звёзды, XP и монеты, push ребёнку, вкладка «От мамы» с кнопкой «Спасибо, мам!».

### Бонусы
- [ ] Серия 5 дней (тест по просмотренному уроку): +200 монет, +200 XP, +3 искры; один раз на цикл.
- [ ] Празднование серии с видео streak-five-v1.mp4 показывается один раз.
- [ ] Обучение: +120 XP, +100 монет, +1 искра, один раз.

### Магазин
- [ ] Фильтры «Всё / Герои / Комнаты / Желания» с иконками, цветами и галочкой выбора.
- [ ] Подфильтры героев «Все персонажи / Обычные / Анимированные».
- [ ] Подфильтры комнат «Все / День / Ночь / Специальные / Анимированные» с иконками солнце / луна / искры / хлопушка.
- [ ] Цены по умолчанию: герой 40, живой 80, комната 120, анимированная комната 200, 300 Robux = 300, картошка 400.
- [ ] Купленные герои и комнаты не показываются в магазине; живые идут первыми.
- [ ] Карточка: превью с кнопкой «плей» у живых, «Послушать», название открывает «Подробнее», цена на кнопке.

- [ ] Диалог подтверждения: «Потратишь N монет. Останется M.», «Подтвердить покупку» / «Пока не покупать».
- [ ] Покупка идемпотентна по requestId; изменённая версия товара отклоняется с просьбой обновить магазин.

- [ ] 8 наборов по умолчанию по 600 XP; 5 этапов по ceil(goal·k/5).

### Искры знаний
- [ ] Искра за каждый уровень; подарочные (родитель 1–20, ачивки, серии, обучение) и золотые (всегда 5★).
- [ ] Колода 6×3★, 3×4★, 1×5★; гарант 5★ не позже 10-го открытия; золотые не трогают колоду.
- [ ] Выпадают только новые вещи; если вещи редкости исчерпаны — 30 / 75 / 200 монет.
- [ ] Бонусы: 3★ 8% → 50 Robux; 4★ 7% → 100, 3% → 250, 8% → картошка; 5★ 10% → 500, 1% → 1000, 15% → картошка.
- [ ] Ручной приз родителя и «Robux в следующей Искре» (≤1000) применяются один раз; гарантированную 5★ ручной выбор не понижает.
- [ ] Результат сохраняется до анимации; повтор и двойной тап не тратят вторую искру; неувиденный приз выдаётся снова кнопкой «Забрать награду».
- [ ] Показ: небо, полёт кометы цвета редкости (голубой / фиолетовый / золотой), силуэт → цвет → предмет, итоговая строка со статусами.

- [ ] Robux и картошка из Искры попадают в «Мои желания».

- [ ] Комплекты 5★ по умолчанию: Cadence, Mart, Dozer; особый подарок первой серии «Лунный подарок Астро» (+500 Robux).
- [ ] Панель нового уровня «Запустить звёздочку / Забрать награду / Позже» со звуком level.

### Мини-игры
- [ ] Три игры с обложками и подписями заданий; статусы «Играть / После одного урока / Закрыто мамой».
- [ ] Награда по умолчанию 30 монет + 20 XP, общий лимит 3 в день; «Наград осталось сегодня: k из N».
- [ ] Родитель: включение наград, монеты 0–50, XP 0–200, лимит 0–20.
- [ ] Игра открывается в полноэкранном iframe с панелью «← КвестКласс»; Назад и Esc закрывают.
- [ ] Сессия на 2 часа со снимком сумм; само открытие ничего не начисляет.
- [ ] Повторная доставка события не начисляет второй раз; при лимите ответ `limit`.
- [ ] Протокол postMessage (complete / return / reward / request-return) с проверкой origin, окна и сессии.
- [ ] Прямой `POST /game-reward` (text/plain, CORS только для origin игр) и резервный `?questReturn=`.
- [ ] Тост «Игра: +N монет и +M XP»; окно выбора игры после пройденного теста.
- [ ] Отмена игрового начисления не возвращает дневной лимит.

### Доступ к играм
