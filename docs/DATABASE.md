# База данных

SQLite (режим WAL), файл `DATA_DIR/questclass.db`.

- **Источник правды о схеме** — `apps/api/src/db/schema/*.ts` (Drizzle; в TypeScript camelCase, в SQLite snake_case).
- **Миграции** — SQL-файлы в [apps/api/src/db/migrations](../apps/api/src/db/migrations). Новая миграция создаётся командой `corepack pnpm db:generate`.
- **Применение** — автоматически при старте, перед приёмом запросов. Перед применением делается снимок базы в `DATA_DIR/snapshots/`.

## Принципы

Подробно — в [CLAUDE.md](../CLAUDE.md), правила 1–5.

- **Одно действие — одна строка.** JSON-колонки только для настроек типа задания (`tasks.config`), значений `settings` и объектов-значений одной строки (варианты ответа, снимок вопроса, интервалы просмотра). Всё, по чему нужен запрос, лежит в отдельных таблицах.
- **Чтение не пишет.** Доступность уроков, баланс и серия вычисляются при чтении.
- **История не удаляется.** Ссылки на историю — `ON DELETE RESTRICT`. Пользователей деактивируют, задания и предметы архивируют. Отмена начисления — новая компенсирующая строка.
- **Баланс XP и монет = `SUM(ledger)`.** У каждой строки журнала уникальный `idem_key`, поэтому повтор запроса не начислит дважды.
- **Миграции только расширяющие**: новые таблицы и колонки с `NULL` или значением по умолчанию. Предыдущая версия приложения работает на новой схеме.

## Таблицы

### Пользователи и вход

| Таблица | Что хранит |
|---|---|
| `users` | админы (родители) и ученики: роль, имя, логин и хэш пароля админа, хэш PIN ученика, `active` |
| `sessions` | сессии входа; токен cookie хранится только как SHA-256 |
| `trusted_devices` | «детские» устройства, с которых ученик входит по PIN |
| `login_throttle` | счётчики неудачных входов (по аккаунту и адресу) |
| `import_tokens` | токены инструмента `lesson-prep` (хранится хэш; отозванные остаются) |

### Настройки

| Таблица | Что хранит |
|---|---|
| `settings` | значения, которые админ поменял; остальные — по умолчанию из реестра `packages/shared/src/settings` |
| `secrets` | ключи API, зашифрованные ключом из `DATA_DIR/master.key` (AES-256-GCM) |

### Учёба

| Таблица | Что хранит |
|---|---|
| `subjects` | предметы: название, встроенный значок или загрузка (`icon_upload_id`), порядок, архив |
| `tasks` | задания любого типа (видеоурок, тест, дело); `config` — настройки типа, проверяются плагином типа |
| `task_assignments` | для кого задание (нет строк — для всех учеников) и его место в очереди ученика |
| `questions` | банк вопросов задания, с версиями: правка или повторный импорт добавляет версию |
| `transcripts` | расшифровка видео (сегменты) |
| `media`, `media_files` | наборы файлов на диске (`DATA_DIR/media/…`): HLS, MP4, картинки вопросов, загрузки кабинета; файлы с размером и SHA-256 |
| `task_revisions` | повторный импорт опубликованного урока, который ждёт решения админа |
| `watch_sessions`, `watch_progress` | просмотр видео: засчитанные секунды по сессиям, объединённые интервалы и процент просмотра |
| `attempts`, `attempt_questions`, `attempt_answers` | попытки теста: снимок показанных вопросов и ответы ученика |
| `retry_requests`, `retry_grants` | просьба о ещё одной попытке и разрешение админа |
| `task_progress` | факты о работе ученика над заданием, одна строка на «эпоху» |
| `progress_resets` | сбросы и «пройти ещё раз»: каждая строка начинает новую эпоху, старые строки остаются историей |
| `chore_completions` | «Я сделал» по делу и проверка админа |
| `streak_days` | дни, когда ученик занимался (для серии занятий) |

### Награды и экономика

| Таблица | Что хранит |
|---|---|
| `ledger` | журнал всех начислений и списаний XP и монет; баланс — сумма строк |
| `reward_reasons` | общие причины ручных наград («Домашняя работа»…) |
| `awards` | выданные вручную награды (название и сумма запоминаются на момент выдачи) |

### Магазин и герой

| Таблица | Что хранит |
|---|---|
| `characters`, `animations`, `rooms` | встроенная библиотека героев, анимаций и комнат (из `apps/api/seed/catalog.json`) |
| `catalog_items` | товары магазина (образ, комната, билет): цена, версия, встроенная картинка или загрузка |
| `purchases` | покупки: снимок товара на момент покупки; оплата — строка `ledger` |
| `wish_requests` | «Хочу использовать» по билетам-желаниям |
| `fulfillments`, `fulfillment_allocations` | выдача желаний и Robux и из каких покупок она взята |
| `learner_characters` | герой ученика: имя, надетый образ, выбранная комната |

### Оформление и служебное

| Таблица | Что хранит |
|---|---|
| `asset_overrides` | встроенные файлы, которые админ заменил своей загрузкой (картинка, анимация, звук) |
| `audit_log` | журнал действий админов и событий безопасности (только добавление) |
| `job_runs` | запуски фоновых задач (очистка старых видео) |
| `__drizzle_migrations` | какие миграции применены (ведёт Drizzle) |

## Что создаётся при первом запуске

- Предметы (`subjects`).
- Библиотека героев, анимаций и комнат и товары магазина (`characters`, `animations`, `rooms`, `catalog_items` из `apps/api/seed/catalog.json`).
- Причины наград (`reward_reasons`).

Повторный запуск не трогает то, что админ уже поменял: в `catalog_items.edited_fields` отмечены поля, которые он правил. Админа создаёт человек через `/setup` по одноразовому коду из лога — см. [DEPLOY.md](DEPLOY.md).
